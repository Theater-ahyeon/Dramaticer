# INBOX：人类追加需求的入口

想加需求、改想法或者反馈问题，就在下面写一条（随便怎么写都行）。agent 会在下一个会话开始时分拣：转成任务、写成 ADR，或者在 HUMAN.md 里向你确认。分拣完的条目会被移走。

## 未处理

1. **每个任务的流程**：先在 HANDOFF.md 写 3–5 行计划，再写测试，再实现；然后对照 AGENTS.md 的不变量 I1–I10 自查 diff，运行 `pnpm check`，最后提交。
2. **阻塞最小化**：任务被 HUMAN 事项阻塞时，优先实现不需要人类的降级方案，并把那个 HUMAN 事项改成"不阻塞"。例如：没有 `SILICONFLOW_API_KEY` 时，先用 BM25 加实体检索，embedding 接口留好位置；需要真人试玩的地方，改用 Playwright 端到端测试，再加上由 LLM 模拟用户的自动试玩（至少 50 轮，并出报告）。
3. **定期审查**：每完成 8 个任务，在 TASKS.md 里插入一个审查任务，检查代码质量、不变量、文档和代码是否同步、测试覆盖率。审查发现的问题写成修复任务。
4. **卡住时的处理**：同一个任务连续 3 次结果是 PARTIAL，就必须分成子任务；分成子任务后还是失败，就标记为跳过，写一条 ADR，然后继续做其他任务。
5. **发布边界**：任何对外发布的动作（git push、发布 npm 包、公开仓库、发帖）都不执行，只把材料准备好，并写进 HUMAN.md。ALL_DONE 的定义是：M7 完成，并且发布材料已经准备好。
