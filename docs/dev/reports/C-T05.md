## API 覆盖率

口径：以本机 SillyTavern 安装里 JS-Slash-Runner 4.8.10 的公开类型定义（`@types/function/index.d.ts` 与 `@types/iframe/{event,script,util,variables}.d.ts`）为准，只记录名字与来源文件，不复制上游源码。快照在 `packages/st-compat/src/st-helper-host/coverage.ts` 的 `ST_HELPER_UPSTREAM_API_SNAPSHOT`，覆盖率由 `summarizeStHelperCoverage()` 计算，`st-helper-consistency` 断言数字。

|口径|上游函数|同名实现|覆盖率|
|---|---|---|---|
|全量公开 API|140|16|11.4%|
|C-T05 任务范围|19|16|84.2%|

任务范围按任务书写明的五组能力：变量读写、事件监听、`triggerSlash`/STscript、生成、读消息与改消息。范围内还缺三个同名函数：

- `insertVariables`：上游的“只插入不覆盖”语义；`insertOrAssignVariables` 已覆盖赋值场景。
- `generate`、`generateRaw`：本实现按 ADR-0122 用 `/gen`、`/genraw` 命令登记后台请求，没有暴露同名全局函数。

另有三个名称在 4.8.10 的公开类型定义里没有、但脚本里仍在用，作为扩展保留：`getVariable`、`insertOrAssignVariable`、`getChatMessage`。

## 共存评测

`ST_BENCH_COEXIST_PLUGINS` 注册 id 为 `st-helper-host` 的适配器（`st-bench/st-helper-plugin.ts`）：

- 关闭组与开启组都用同一份 ST 内容映射（`st-content`），只差本插件。
- 开启组在每轮回复写入后做本插件的宿主侧工作：读取角色卡脚本库、从新楼层提取 HTML 状态栏并把渲染请求送进沙箱。脚本执行在浏览器 iframe 里，Node 里的批次没有 iframe，所以脚本正文不会执行。
- 两组提示词逐字节相同（测试直接比较假正文客户端收到的 26 次请求）；四项指标只反映宿主侧管线是否改变了原生上下文。

合成批次（`test/st-helper-coexist.test.ts`，1 张合成卡、5 轮、假正文客户端与假裁判，零网络）：

|指标|关闭|开启|样本量（关/开）|判定|
|---|---|---|---|---|
|矛盾率|0%|0%|8/8|持平|
|编造回忆率|0%|0%|4/4|样本不足（门槛 5）|
|盲测胜率（开启侧）|—|—|10/10|持平（10 次全部平局：两组文本完全相同）|
|首字 P90|1 毫秒|1 毫秒|5/5|持平|

平局不计入胜负：`judgePairwise` 在两份文本完全相同时直接判平局、不调用裁判。`compareBlindWin` 因此按“非平局判定”计算胜率，全部平局时判定为持平（ADR-0124）。

这一批只验证入口、宿主侧管线与报告格式；真实渠道的对照用：

```bash
node packages/st-compat/dist/st-bench/cli.js coexist --config <配置.json> [--out <目录>]
```

配置的 `plugins` 写 `["st-helper-host"]`，卡用带脚本库与 HTML 状态栏的素材；私有报告的实跑数字按 `docs/dev/reports/C-T02.md` 的口径补记。

## C-T05 总验收逐条核对

|验收项|证据|
|---|---|
|酒馆助手 API 覆盖率与一致性测试达到提案口径|140 个上游函数里同名实现 16 个；任务范围 19 个里实现 16 个；31 条一致性用例，覆盖清单里每个函数至少一条；覆盖率数字由测试断言|
|修改消息不触碰原文（I4）|`setChatMessages` 改正文经 `applyMessageModification` 新建兄弟楼层，原楼层逐字节不变；只改 `is_hidden` 写显示状态；一致性用例与 `st-helper-host` 测试断言|
|脚本在沙箱里运行（ADR-0041 A10）|`StHelperSandboxHost` 只收发纯 JSON；web 沙箱 `sandbox="allow-scripts"`、无 `allow-same-origin`、`default-src 'none'`；e2e 里脚本读不到父页面、`localStorage`、`indexedDB` 与网络|
|脚本发起的生成走后台渠道并在 Trace 单独计数（I6、I11）|`StHelperGenerationQueue` 复用 EJS 调度器的卡级上限，`/gen`、`/genraw` 只登记；Trace 用 `kind: "generation"`；`st-helper-generation` 5 个测试 + 一致性用例|
|脚本与正则的变量写入经过结算器（I12）|变量存储与 EJS 共用；`character` 写入经 `createStEjsMvuVariableBackend` 与结算器落成 `mvu`；一致性用例读回台账|
|开启与关闭的对照评测里原生指标不明显变差（ADR-0040）|合成批次四项指标都有数字与样本量，`degraded` 为空；两组提示词逐字节相同|
|插件权限必须声明（I18）|未声明调用返回拒绝并记录 `permission`/`denied`；权限清单校验未知、重复与依赖缺失|
|HTML 状态栏与开场页不改原文（I8）|`extractStHelperHtmlFragments` 只认三种载体；快照写 `PluginDisplayState`；一致性用例与 `st-helper-html` 测试|
|回合内插件钩子有时间预算（I17）|沙箱共用 `scriptTimeoutMs`，超时终止并写 Trace；脚本渲染也走同一套超时|

## 已知边界

- 共存批次不执行脚本：Node 里没有 iframe，脚本执行由沙箱单元测试与浏览器用例覆盖。因此这一批的两组提示词必然相同，盲测全部平局；指标说明的是“宿主侧回合管线不改变原生上下文”，不能替代带真实脚本的真实渠道批次。
- 生成函数名 `generate`/`generateRaw` 没有暴露；脚本要用 `/gen`、`/genraw` 与 `/genresult`。未实现的分组见“API 覆盖率”。
- iframe 里的宿主 API 全部异步：`postMessage` 不能同步取返回值，脚本必须 `await`。这是与上游同步 API 的已知差异，一致性用例记录该协议事实，不伪造同步语义。
- 上游 JS-Slash-Runner 的许可证是 Aladdin Free Public License；本实现只按公开类型定义里的函数名与文档描述的行为独立编写，没有复制或移植源码，见 HUMAN-18。
