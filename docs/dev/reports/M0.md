## 二、设计假设的实测结论

### 被证实的

| 假设 | 实测 | 结论 |
|---|---|---|
| 大型对话的体积被重复的表格状态与插件字段占据 | 银麒赎世 231 楼 35,425,713 字节，其中对话头部 24,814,167 字节（70.1%）、其他字段 7,376,431 字节；其他字段里的最大单项是 `hash_sheets` 14,378,138 字节 | 成立；需要被替换的是 ACU 表格载荷与插件记账字段 |
| 预设即程序 | 58 个预设、8004 个条目（启用 2361）、485 个 marker、提示词正文 9,824,772 字节；`setvar` 4911 次、`getvar` 3584 次、`addvar` 522 次 | 成立，条目数远高于设计阶段的估计 |
| 正则同时承担展示与上下文管理 | 928 条：渲染 HTML 214 条、内联脚本 141 条（渲染类合计 38.3%）；删除内容 319 条（34.4%）、删除思考链 76 条（8.2%）；带深度限制 356 条，`markdownOnly` 657 条、`promptOnly` 449 条 | 成立；“显示 / prompt / 记忆”三视图的拆分有数据支撑 |
| ACU 是短状态查表，不是事件记忆 | ACU 覆盖 91/386（23.6%）：状态题 88/236（37.3%）、事件题 3/150（2.0%）；按答案长度 1 字符 81.8%、2–3 字符 63.9%、4–9 字符 36.2%、10 字符以上 0.0% | 成立；ACU 只能作为状态题的对照 |
| 世界书规模足以要求检索 | 381 个条目（启用 370、常驻 146），641 个去重后的主关键词，卡内嵌 328 条 | 成立；常驻条目可以直接注入，其余需要检索 |
| 正则自动升级有实际空间 | 启用的 637 条里 300 条可升级（47.1%）；全部 928 条的策略分布是块策略 252 条、渲染器 175 条、沙箱渲染器 148 条、保留原正则 353 条 | 成立；兼容线的自动升级按 47.1% 估算投入 |

### 被实测修正的

| 原假设 | 实测 | 处理 |
|---|---|---|
| 每楼 60–150 KB | 三个对话分别为 36.2 KB、24.3 KB、153.4 KB，平均 54.3 KB | DESIGN §2 改为 24–153 KB，并写明只有最大的对话达到 150 KB 量级 |
| 状态以整份快照塞进每一楼 | MVU 变量合计 1,331,492 字节（占总文件 2.0%）；重复存储的主体是 ACU 的 `hash_sheets`（14.4 MB）与对话头部的表格历史（25.8 MB） | DESIGN §2 的“本质”列改为插件表格与单元格历史 |
| 存储体积降低一个数量级以上 | 楼层原文 8,848,166 字节、思考内容 1,078,926 字节、状态 diff 264,601 字节，合计 10,191,693 字节，是 66,397,069 字节的 15.3%（6.5 倍）；合计平均单楼约 8.3 KB。三个对话分别为 5.5、3.6、10.0 倍。原文在 I4 下不可压缩 | ADR-0008；DESIGN §14 的目标改为“合计平均单楼原文加 diff 不超过 10 KB”（实测 8.3 KB） |
| 状态题与事件题可以用同一个召回指标对照 | 状态题：ACU 37.3%、BM25 8.1% @20；事件题：BM25 96.0% @20（83.3% @5）、ACU 2.0% | ADR-0008；DESIGN §14 与 M2 过关标准改为按题型分层 |
| 重复度会在多数对话里持续上升 | 相邻回复 4-gram Jaccard 平均 0.119、0.108、0.119，峰值 0.163、0.137、0.143；只有 1 个对话检出持续上升（第 82 楼），另两个没有 | M3 的重复检测使用 embedding 节拍与场景类型序列，字符 n-gram 只保留为离线基线 |
| 58 个预设的可用率可以在 M0 定目标 | M0 只验证了解析与结构往返（58/58），没有验证导入后能否生成一轮 | DESIGN §14 写为目标在兼容线开始前用导入清单实测后确定 |

## 五、遗留事项

- 230 个对话的导入成功率尚未验证；M0 只验证了 3 个对话、3 张卡。
- 58 个预设的解析与结构往返已验证，生成一轮的可用率尚未验证，目标在兼容线开始前确定。
- 事件题答案质量依赖 HUMAN-03 的人工抽查，该项不阻塞任务。
- bge-m3 只验证了单次调用（200、1024 维、0.31 秒）；限流与稳定性留到 M2。
- pi-ai 的流式、工具调用、思考输出、abort 后续写、Gemini 原生自定义 baseUrl 全部待 M1-T01 验证。
- 正文模型的端到端单轮生成没有在 M0 运行；M0 的 LLM 调用只用于离线出题。

## 六、结论

M0 的目标“有数据，能度量”达成：体检、BM25 基线、ACU 对照、状态题与事件题、导入回放都有可重复的命令和数字。设计假设已按实测校准（ADR-0008），不变量没有违反项。门禁通过，转入 M1。

## 附录：验收脚本

本次验收在 `.devloop/scratch/` 里用编译后的模块做了两项检查，脚本与临时数据库在提交前删除：

- 存储估算：对每个对话逐楼累加 `mes` 与其他 swipe 的正文，再加 `extra.reasoning` 与状态 diff，得到原生存储的字节数。
- 导入回放：`importChatFileToStore` 写入临时 SQLite，逐楼执行 `getStateDiffsAlongPath` 并累加，与解析出的当前 swipe 的 MVU 快照做深度比较（空对象按 ADR-0006 视为没有更新）。
