### 状态层答案正确率的测量方式

ADR-0023 决定状态题在运行时由状态层回答，M2-T99 用提问楼层的快照值与标准答案的一致率作为状态层指标。本次把这个指标做进评测管线，后续每次 `memory-eval` 都会重新计算：

- 状态题文件新增 `path` 字段（完整状态路径）；`readQuestionFile` 对状态题要求非空字符串数组，事件题不读取该字段。
- `collectMemoryEval` 对每道状态题调用 `getStateSnapshot(askAtNode)`，按路径取值，并按 MVU `[值, 说明]` 的规则取出标量，与题目的标准答案比较；取不到路径时单独计数为缺失。
- 报告新增「状态层答案正确率」一节，按对话与合计给出题数、一致数、路径缺失数与正确率。
- 结果：对话 1 71/71、对话 2 65/65、对话 3 100/100，合计 236/236，路径缺失 0。

这说明导入时生成的 diff 与按路径回放出的快照在全部 236 道状态题上与原始 MVU 快照一致，状态层可以直接回答这些题目；文本召回 13.6% 是检索层的成绩，两者分开报告。

## 三、设计假设与实测

| 假设 | 实测 | 结论 |
|---|---|---|
| 状态题可以用文本检索达到 45% | 融合 @20 13.6%，BM25 14.0%，向量 13.1% | 不成立；证据楼层是状态变化楼层，原文里通常没有变量值。改由状态层回答（ADR-0023），实测 100% |
| 多路融合不会低于单独 BM25 | 事件题 @5 融合 83.3%，BM25 85.3%；@20 融合 98.0%，BM25 97.3% | 部分成立；@20 更好，@5 被向量与实体候选挤掉 BM25 前几名，权重需要调整 |
| 状态快照按楼层缓存可以避免每轮回放 | 随机分支树上快照与 diff 回放的全部节点一致；同一节点第二次读取不重算；追加 diff 后后代缓存失效 | 成立 |
| 实体别名可以把相关事件排到前面 | 别名用例把目标事件排到更重要的无关事件之前 | 成立 |
| 后台任务与主循环可以分开 | `runChatTurn` 不调用后台处理器；后台类型只有 `work` 执行；live 3 轮对话里主循环请求数与工具轮数受限 | 成立 |
| 读取工具轮数可以限制在 2 轮 | 连续请求工具时第 3 次请求后停止并保留正文；文本标签模式没有工具定义 | 成立 |
| 事件表可以在评测中建立 | 主路径约 1219 个已确认楼层，每个一次后台请求；渠道约 2.7 次/分钟，超过 7 小时 | 未建立；事件路记 0，报告如实标注 |
| 章节摘要与主线摘要的窗口可以参数化 | 窗口参数变化时范围正确；不足窗口、已有摘要时不调用模型 | 成立 |

- HUMAN-03 的事件题人工抽查仍未完成，不阻塞任务。
- 230 个对话的导入成功率尚未验证。
- 显示视图与正则执行层分别属于 M4 与兼容线，M2 没有实现。
- live 测试的 3 轮对话中，模型有 1 到 2 轮主动调用读取工具；写入工具（`state_update`、`plot_note`）在这几次运行里没有触发，写入行为是否稳定仍依赖提示词与后续里程碑。

## 七、结论

M2 的楼层树、状态层、记忆引擎、后台任务与读取工具链路全部按任务清单交付，门禁与 live 测试通过，I1–I10 没有违反。状态层在 236 道状态题上与标准答案 100% 一致；文本检索的成绩按 ADR-0023 如实报告，事件题 @20 达标、@5 未达标，缺口有明确原因。M2 收尾，转入 D-T04 与 M3 的 Director。
