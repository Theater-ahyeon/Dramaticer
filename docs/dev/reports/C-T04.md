## 一致性用例

用例表在 `test/st-ejs-consistency.test.ts`，每行记录来源、上游文档行为、输入与期望输出。

|来源|用例|断言|
|---|---|---|
|世界书|`getwi` 省略世界书名|读取当前世界书；条目正文再次进入模板处理|
|世界书|`recursive`|条目正文触发的其他条目一起返回，顺序按激活|
|世界书|关键词与常驻激活|关键词命中的条目与 `constant` 条目都进入激活数据|
|世界书|内容注入|`[GENERATE:BEFORE]`/`[GENERATE:AFTER]` 收走后续文本并保留指令原文|
|世界书|装饰器|`@@if` 用模板局部变量求值，表达式报错带原文|
|预设|`getpreset`|省略名称时读取当前预设|
|预设|`getqr`|按标签读取快捷回复|
|预设|`generate`|只登记请求并返回 id，`drain` 之后读取正文|
|预设|激活正则|替换函数拿到 `this.getvar`|
|角色卡|`getchar`|读取单个字段|
|角色卡|`getCharData`|读取开场白与整张卡|
|对话片段|`getChatMessage`|负下标从最新一楼开始|
|对话片段|`getChatMessages`|按角色筛选楼层|
|对话片段|`matchChatMessages`|在楼层范围内匹配文本|
|对话片段|变量函数|同一运行时里写入后立即读到|

另有两组内容范围用例：

- 预设静态段、`history` 与 `lore` 槽位执行 EJS；写作契约段、`state` 等 harness 槽位逐字节不变。
- 模板里的 `setvar` 经待结算视图与结算器落成 `mvu` 事实；楼层原文逐字节不变。

## C-T04 总验收逐条核对

|验收项|证据|
|---|---|
|EJS 模板的一致性用例全部通过|`st-ejs-consistency` 18 个测试；全部 EJS 测试 131 个通过|
|沙箱逃逸测试通过|`st-ejs-sandbox` 10 个测试：`process`、`require`、`fetch`、`Buffer`、构造器链与动态 `import` 都拿不到；超时后同一沙箱继续执行|
|模板执行不影响台账事实（I12）|变量写先 `stage` 由结算器校验，再 `commit` 成本楼层 `mvu` diff；非法路径直接抛错；流水线与一致性用例断言原楼层原文不变|
|EJS 只作用于来自 ST 的内容，不修改 harness 槽位|`wrapProviders` 只包 `history` 与 `lore`，其余槽位返回同一对象；`renderTemplate` 跳过写作契约；`st-content-ejs-pipeline` 与一致性用例逐字节比对|
|模板执行与世界书递归激活计入回合内时间预算，超时写入 Trace|`StEjsRuntime.render` 每次执行按 `remainingMs()` 启动，嵌套 `getwi` 沿用同一预算；`st-ejs-budget` 8 个测试、`turn-hooks` 3 个测试、`explain` 1 个测试|
|开启与关闭的对照评测里原生指标不明显变差|见下节；合成批次四项指标均有数字与样本量，没有变差项|

## 共存评测

`ST_BENCH_COEXIST_PLUGINS` 注册 id 为 `st-ejs` 的适配器：

- 关闭组用同一份预设、世界书、深度注入与角色卡映射，只关闭 EJS 流水线（`buildStContentCoexistResult(..., { ejs: false })`）。
- 开启组在相同内容上执行 EJS：预设静态段、`history`/`lore` 槽位在进入上下文前渲染，变量视图接台账 `mvu` 子树。
- 两组输入相同，四项原生指标只反映模板执行与它带来的上下文变化。

合成批次（`test/st-ejs-coexist.test.ts`，1 张合成卡、5 轮、假正文客户端与假裁判，零网络）：

|指标|关闭|开启|样本量（关/开）|判定|
|---|---|---|---|---|
|矛盾率|0%|0%|8/8|持平|
|编造回忆率|0%|0%|4/4|样本不足（门槛 5）|
|盲测胜率（开启侧）|—|100%|10/10|更好|
|首字 P90|1 毫秒|0 毫秒|5/5|持平|

这一批只验证入口、EJS 作用范围与报告格式；假客户端的胜负由固定标记决定，不代表真实模型效果。真实渠道的对照用：

```bash
node packages/st-compat/dist/st-bench/cli.js coexist --config <配置.json> [--out <目录>]
```

配置的 `plugins` 写 `["st-ejs"]`，卡用带 EJS 预设、世界书与角色卡模板的素材；私有报告的实跑数字按 `docs/dev/reports/C-T02.md` 的口径补记。

## 已知边界

- 模板发起的生成在共存批次里没有触发：批次只有正文与裁判客户端，没有后台客户端；生成行为由 `st-ejs-generation` 9 个测试覆盖（I6、I11）。
- 第一轮没有楼层时预设静态段按 `nodeId: null` 渲染，变量只留在运行时内存、不写台账；从第二轮起变量视图按台账快照读写，与 C-T04.c.c 的楼层锚点语义一致。
- 卡内 Zod 脚本、`triggerSlash` 与酒馆助手 API 属于 C-T05。
- 上游 ST-Prompt-Template 的许可证是 AGPL-3.0，本实现按公开文档描述的行为独立编写，没有复制源码；见 HUMAN-17。
