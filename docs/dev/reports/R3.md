## 四、不变量复核

### I6：回合模式只能由玩家手动切换

| 检查点 | 结果 |
|---|---|
| 模式与软上限只有一个解析口 | 通过：`chat/turn.ts` 的 `resolveTurnMode`，单轮参数优先于故事设置；`runChatTurn` 与 `generateAssistantTurn` 都调用它 |
| 没有任何按运行状况切换模式的代码路径 | 通过：`turnMode` 的写入只有存储层的设置保存（`store.updateStorySettings`），读取只有 `resolveTurnMode`；执行器只在 `rounds >= maxReadRounds` 时收束，不再改模式 |
| 失败、重试与设置变化都不改模式 | 通过：`turn-mode.test.ts` 的三条用例；Trace 的 `turnMode` 记录解析结果 |
| 请求深回合直接失败且不留下空分支 | 通过：“故事设置锁定深回合时直接失败并指出 R3b，不追加用户楼层” |
| server 不自行切模式 | 通过：`packages/server/src` 没有 `turnMode` 引用，回合路径走 `runChatTurn` 的默认解析；设置接口通过 `STORY_SETTINGS_UPDATE_KEYS` 接受玩家显式提交的 `turnMode` |
| UI 尚不展示深回合 | 通过：`packages/web` 尚未创建；R5-T05 的验收已写明深回合未实现前不展示该选项 |

### I13：尊重模型能动性

| 检查点 | 结果 |
|---|---|
| 不强制模型每轮调用工具 | 通过：读取工具是可选项，模型不调用时执行器直接收束（`chat-tool-loop.test.ts` 的首轮直接回复用例；R3-T04 的 20 轮里 17 轮没有工具轮） |
| 不强制输出固定结构 | 通过：结构化工具定义只在 `function-call` 模式提供；`text-tags` 模式只解释标签写法；`block_format` 默认关闭，开启时写明“要不要写、写几条，按剧情需要决定” |
| 提示词里没有剧本式命令 | 通过：`WRITING_CONTRACT` 是四条原则，`TEXT_TAG_PROTOCOL` 与 `FUNCTION_CALL_PROTOCOL` 只描述提交格式，不规定本轮必须发生什么 |
| 预算与上限只用于防失控 | 通过：读取工具软上限默认 3，达到上限正常收束；R3-T04 里没有任何一轮触发 `capped` |
