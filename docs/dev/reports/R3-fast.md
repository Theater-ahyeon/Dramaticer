## 四、观察

- 第 1、2、9 轮的读取工具轮没有达到软上限，执行器按模型请求正常收束；没有任何一轮出现 `capped`。
- 第 20 轮以 `toolUse` 结束，是模型在正文之后调用写入类工具（`state_update` / `plot_note`），写入只收集不执行，属于预期行为。
- 路由先做了一次体检：`function-call`、`streaming`、`thinking` 均支持。没有体检记录时该别名走文本标签模式，读取工具不会提供给模型；本次运行使用带体检记录的配置，读工具路径因此被真实执行到。
- `auto` 路由的 Trace 模型名是 `group/auto-deepseek-v4-1-flash`，与配置里的 `auto/deepseek-v4.1-flash` 不同，报告以 Trace 为准。
