## 兼容报告

`buildStContentCompatReport` 从预设、角色卡与 `mapStPreset` 的结果生成 `StContentCompatReport`，`renderStContentCompatReport` 输出 Markdown。报告包含：

- 每个启用条目的标识、名称、类型、角色、字符数、估算 token、原因与分类；进入 prompt 的静态段与深度注入单独合计 token，无法映射的启用条目另计。
- 未识别的 marker（`unknown-marker` 条目）。
- 角色卡未知字段与扩展键。
- 无法映射的深度与角色：`role`、`injection-depth`、`injection-position`、`marker-injection`、`persona-depth`，细节只写角色值、深度、位置或 marker 标识。
- 同一顺序组里同时启用的同名或同标识条目，不推断互斥。
- 总结类与规划类条目；两类条目仍按酒馆的启用状态留在 prompt 里。
- 角色卡内嵌世界书的条目数、启用数、关闭数与启用条目的 token；只统计，不输出正文。
- 预设与角色卡的问题代码与细节。

报告与摘要只含标识、名称、计数、token 与原因，不含提示词正文；测试用一组正文标记逐条检查 Markdown、摘要与序列化结果。

CLI：

```bash
node packages/st-compat/dist/st-bench/cli.js preset \
  --preset <预设.json> --card <角色卡> [--out <报告.md>]
```

## 共存开关对照接入

`ST_BENCH_COEXIST_PLUGINS` 注册 id 为 `st-content` 的适配器：

- 关闭组使用默认模板与基础槽位。
- 开启组用 `mapStPreset` 生成模板，宏引擎带角色卡字段与当前路径楼层；角色卡内嵌世界书交给 `createStWorldInfoProviders`，`worldInfoBefore/After` 进入原生 `lore` 槽位，深度条目经 `createStHistoryProvider` 叠到历史槽位，预设正则按允许开关收集。
- 世界书槽位来源加 `st-content：` 前缀，模板静态段保留 `template:st-content-preset/...`，Trace 能把 ST 内容与原生槽位分开。
- 共存配置的卡新增可选 `preset`；使用 `st-content` 而缺少预设时直接报错。

测试用合成预设、合成角色卡、假正文客户端与假裁判跑开与关两组各 5 轮，验证入口与报告格式；这不是真实模型效果评测，不调用玩家本机 ST 额度（I14）。样本量与指标：

|指标|关闭|开启|样本量（关/开）|判定|
|---|---|---|---|---|
|矛盾率|0%|0%|8/8|持平|
|编造回忆率|0%|0%|5/5|持平|
|盲测胜率（开启侧）|—|50%|10/10|持平|
|首字 P90|1 毫秒|1 毫秒|5/5|持平|

报告末尾的「明显变差」一节在达到 ADR-0100 的门槛时列出项目与样本量；上面的固定假客户端没有触发变差。真实渠道的对照评测用 `st-bench coexist --config <配置.json>` 运行，配置与输出格式不变。
