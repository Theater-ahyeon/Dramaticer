# C-T01.c 逐条比对与覆盖报告

## 做什么

把 ST 录制请求与 Dramaticer 在相同输入下组装的请求规范化后逐条比较。规范化只保留消息角色、SHA-256 正文哈希、正文长度、采样参数与流式开关；模型名不参与比较。忠实模式关闭记忆、台账、导演、写作契约等原生功能，只映射预设条目、角色卡字段、聊天历史、深度注入与预填充。

产物：

- `packages/st-compat/src/st-bench/compare.ts`：规范化、逐位比较、覆盖率汇总、报告渲染、批次比对。
- `packages/st-compat/src/st-bench/faithful.ts`：忠实模式组装。
- `packages/st-compat/src/st-bench/cli.ts`：`st-bench compare [--sandbox] [--batch] [--limit]`。
- `packages/core/src/context/template.ts`：静态段增加可选 `role`，默认 `system`。

批次产物在 `eval-private/st-sandbox/runs/<批次>/compare/`：`report.md`、`diffs.jsonl`、`summary.json`。报告只含统计、路径、哈希、长度与条目标识。

## 覆盖率口径

- 消息覆盖率 = 位置、角色与正文哈希都一致的消息数 / ST 录制请求的消息数。
- 采样参数覆盖率 = 一致且双方都出现的字段数 / 双方至少一侧出现的字段数。
- 无法映射的功能列入「不支持」，作为差异条目计数，不计入已支持功能的差异。
- 深度注入位置由消息位次体现；预填充作为末尾的 assistant 消息参与比较。

## 片段历史口径

驱动在切换预设后把沙箱的 `openai_max_context` 设为 2,000,000（ST 对自定义模型允许的最大值），并用 `/api/settings/get` 读回确认。这样预算不再替预设决定送不送历史；历史是否进入请求只由预设的 `prompt_order` 与驱动打开的片段决定。

`compare` 为每条请求输出历史诊断：片段非空楼层数、在录制请求里找到的楼层数与未包含时的原因。用户消息按 ST 的 `names_behavior` 加名字前缀后再匹配。

## 共存开关对照（C-T01.d）

`packages/st-compat/src/st-bench/coexist.ts` 提供同一批卡在兼容插件关闭与开启时各跑一遍的入口，供 C-T02–C-T05 共用：

- `runCoexistComparisons` 对配置里的每个插件分别执行关闭与开启两组；每组使用独立的数据库、相同的角色卡、相同的已有片段与相同的脚本玩家消息。
- 插件通过 `CoexistPluginAdapter.apply` 接入，只允许改写模板与槽位提供者；关闭组使用基础模板与槽位。已注册的适配器放在 `ST_BENCH_COEXIST_PLUGINS`，C-T02–C-T05 在那里加入自己的实现。
- CLI：`st-bench coexist --config <配置.json> [--out <目录>]`。配置声明正文模型、裁判模型、结构化输出方式、插件 id、每张卡的角色卡路径、可选片段路径、脚本消息与记忆题文件；输出目录必须在私有根目录内部。
- 报告写入 `<输出>/<插件>/report.md`，指标写入 `metrics.json`，均只含数字、样本量与开关状态，不含提示词与回复正文。

四项原生指标复用 R2 的口径：

|指标|关闭组|开启组|样本量|
|---|---|---|---|
|矛盾率|`contradicted / (consistent + contradicted)`|同左|判为一致或矛盾的题目数|
|编造回忆率|`fabricated / fabricatedJudged`|同左|被判定的编造题数|
|盲测胜率|—|开启侧在两顺序盲评里的胜率（平局不计入胜负）|顺序级判定次数|
|首字延迟|Trace 的 P90|同左|有首字时间的轮数|

变差门槛：矛盾率与编造回忆率开启侧比关闭侧高 5 个百分点；盲测胜率低于 45%；首字 P90 超过关闭侧 1.2 倍且多 100 毫秒。任一侧样本少于 5 时写“样本不足”，不判变差。报告末尾单独列出达到门槛的项目与样本量。

入口只使用 Dramaticer 配置的模型渠道，不启动沙箱 ST，也不调用玩家本机 ST 额度（I14）。测试用假插件、假正文客户端与假裁判验证两组跑完、四项指标与变差清单；`packages/st-compat/test/st-bench-coexist.test.ts` 3 个测试通过。

## 结论

采样参数已经能逐个对齐，片段历史的存在性与缺失原因可以逐条读出。消息差异集中在预设内容尚未映射：世界书、宏、正则、摘要预设的条目合并、角色内嵌世界书与未覆盖的采样字段逐条列入不支持，留给 C-T02 的 `st-content` 实现。

`core` 只新增通用的静态消息角色，不出现 ST 概念（I1、I15）。

门禁通过：197 个测试文件、1740 个测试、5 个跳过。
