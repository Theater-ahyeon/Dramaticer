# F0 对话语料统计（F0-T01、F0-T02.a）

生成时间：2026-11-07T17:43:10.295Z

扫描 3 个 ST 数据目录的 `chats/` 子目录（只读），共 406 个 jsonl 文件；按文件名去重后 265 个对话，重复的文件名有 87 组。同名副本保留目录顺序靠前的那份。

## 口径

- 楼层：jsonl 第一行是对话头部，其余每个非空行算一个楼层。
- 正文：每条消息当前显示的文本（`mes`），不含其他 swipe、变量、状态表、系统提示、角色卡与世界书。
- token 估算：与 core 的 `createTokenEstimator` 相同，CJK 字符按 1.5 个字符算 1 个 token、其余按 4 个字符算 1 个 token，向上取整后按楼层累加。
- 容量占比：把对话全部楼层的当前正文 token 之和与 131072（128K）、204800（200K）、1048576（1M）比较。实际请求还要加上系统提示、角色卡、世界书与模板，所以这是乐观估计。
- 重 roll 率：助手楼层里 `swipes` 数量大于 1 的占比；缺 `swipes` 字段的助手楼层按 1 条 swipe 计。
- 百分位用最近秩法（P 对应升序第 ⌈P×N⌉ 个值）。
- 近期与早期：按所选文件的修改时间升序把对话分成两半，较旧一半（1970-01-21 至 2026-08-16）与较新一半（2026-08-16 至 2026-11-07）。部分副本的修改时间是复制时间，这一分组只能近似反映写作时间。
- 助手生成耗时：`gen_started` 到 `gen_finished`，缺失时读 `extra` 里的同名字段；结束早于开始或超过 24 小时的记录丢弃。
- 首字延迟：`extra.time_to_first_token`（毫秒）换算成秒。
- 玩家思考间隙：上一条助手楼层的 `gen_finished`（缺失时用它的 `send_date`）到该用户楼层的 `send_date`，只统计同一会话段内、间隔非负的相邻对。
- 会话段：按楼层 `send_date` 升序，相邻两层间隔超过 30 分钟算新段；对话跨度是最后与第一层 `send_date` 之差。
- 楼层深度：按非 system 楼层的序号计，1 到 10、11 到 50、51 到 100、101 到 200、201 以上分桶。
- 标签块与代码块占比：用 core 的块解析器统计已闭合的顶层标签块，加上块外整行以 ``` 开头的代码围栏；未闭合的块按正文处理。标签名取语料里出现至少 5 次的无属性开标签，因此带属性的 HTML 标签不计入，这个占比是保守估计。
- 编辑信号：助手楼层的 `mes` 与 `swipes[swipe_id]` 不同时按形态分类：去掉空白后相同、末尾追加正文、只改标签块（去掉标签块后正文相同）、去掉标签块后正文少量变化（公共前缀不低于 80% 且长度差不超过 120 字符）、其余算正文大改。

## 与方案评审提案统计的差异

- 与 `docs/proposals/v3-review.md` 的 0.1–0.6 相比，生成耗时、首字延迟、回复 token、思考 token 与按楼层深度的重 roll 率一致（相差不超过 1 个百分点或 1 个 token）。
- 玩家思考间隙：本文 P50 与 P90 略低，因为只统计上一条是助手楼层、用 `gen_finished`（缺失时用 `send_date`）计算的非负相邻对，并丢弃超过 30 分钟的跨段间隔。
- 标签块与代码块占比：本文只统计已闭合、不带属性的标签块（core 块解析器不匹配带属性的标签），带属性的 HTML 按正文计；提案的正则估算会重复计算嵌套标签。两个口径不能互换使用。
- 楼层级生态字段：本文按字段存在计数、范围是非 system 楼层；提案的表格（1,140）与工具调用（127）口径不同，可能只计算表内有内容或按 swipe 计的楼层。
- 编辑分类：本文用块解析器剔除标签块后比较正文，并把“去掉标签块后正文相同”单列成“只改标签块”；提案的“新增标签块 2”只覆盖追加块，本文的 155 个包含状态栏与变量块被整体改写的情况。
- 对话规模与“最后一楼”统计相差 1 到 8 个对话：本文按文件名去重后保留目录顺序靠前的一份，楼层计数不含 system 楼层。
