## 变量结构的校验口径（zod 卡）

- MVU 卡用 zod schema 描述变量结构，schema 由 `$meta`（`extensible`、`required`、`recursiveExtensible`、`template`）、数组标记 `$__META_EXTENSIBLE__$` 与 `$arrayMeta` 生成。
- Dramaticer 消费的是这棵结构的 JSON 投影：`type`、`properties`、`elementType`、`extensible`、`recursiveExtensible`、`template`、`required`。`buildMvuInitState` 生成它，`parseMvuSchema` 原样读回，`validateMvuSchemaValue` 按它给出完整路径的问题列表；一致性用例验证往返后的校验结果一致。
- 根级 `strictSet`、`strictTemplate`、`concatTemplateArray` 不写进结构 JSON，由 `MvuState.options` 携带；缺省为 `false`、`false`、`true`。
- 不执行卡内 zod 脚本本身。需要执行时由 C-T05 的酒馆助手宿主在沙箱里运行，当前实现只读结构化数据，不加载任何卡内 JS。

## 共存评测

`ST_BENCH_COEXIST_PLUGINS` 注册 id 为 `st-mvu` 的适配器：

- 关闭组用默认模板与槽位；开启组同样不改模板与槽位，每轮回复里的 `<UpdateVariable>` 经 `MvuLedgerSession` 写成该楼层的 `mvu` diff。
- 初始变量在第一个助手楼层提交；第二轮起 `state` 槽位带着变量进入上下文。
- 报告说明里只出现条目数与计数，不含正文。

合成批次（`test/st-mvu-coexist.test.ts`，1 张合成卡、5 轮、假正文客户端与假裁判，零网络）：

|指标|关闭|开启|样本量（关/开）|判定|
|---|---|---|---|---|
|矛盾率|0%|0%|8/8|持平|
|编造回忆率|0%|0%|4/4|样本不足（门槛 5）|
|盲测胜率（开启侧）|—|100%（8 次非平局判定全胜，另有 2 次平局）|10/10|更好|
|首字 P90|0 毫秒|1 毫秒|5/5|持平|

这一批只验证入口、写入口径与报告格式；假客户端的胜负由固定标记决定，不代表真实模型效果。真实渠道的对照用：

```bash
node packages/st-compat/dist/st-bench/cli.js coexist --config <配置.json> [--out <目录>]
```

配置的 `plugins` 写 `["st-mvu"]`，卡用带 `[initvar]` 世界书的角色卡；私有报告的实跑数字按 `docs/dev/reports/C-T02.md` 的口径补记。

## 已知边界

- 状态栏 HTML 渲染与占位符替换是显示副作用，由 `applyMvuStatusBarRefresh` 写在插件显示状态里，不在共存评测的指标里体现。
- 适配器不会自动关闭 `[initvar]` 世界书条目：按酒馆语义，这类条目应当不常驻、无关键词，原生 `lore` 槽位不会注入它。
- 卡内 zod 脚本、`{{get_message_variable::}}` 之类的宏与酒馆助手宿主属于 C-T04、C-T05。
