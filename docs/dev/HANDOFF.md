## 注意事项
- `.env` 已由人类填写，**不要覆盖**。
- 私有数据（`eval-private/`、`data/`、`.env`）不能进入测试数据、提交、文档或日志；报告只写统计数字，不写对话原文。R6 与 X1、X2 的 JSON 含回复与答案，只能放在私有目录。场记对照的报告含楼层 id 与台账值，只能放在 `eval-private/`。
- 导入审计的 `content` 是导入时的原文快照，与 `lore_entries.content`（去掉首尾空白）分开保存；体检页要显示条目正文时优先读审计行，停用条目没有 lore 行。
- 审计的 `source` 必须与 lore 条目同构；`importWorldInfoLore` 是唯一写审计的路径，`importCharacterBookLore` 通过它转发。不要绕过它在别处拼来源。
- 审计写入在 lore 写入之后：lore 抛错时不留半截审计。重导入时 `created_at` 保留第一次导入的时间，`updated_at` 每次更新。
- `kind_source = rule` 的条目不要用 `setImportAuditEntryKind` 写成别的类型；要改类型必须同时给出 `player` 或 `model`。回到规则判定时 `kind` 必须等于 `rule_primary`，否则直接报错。
- 只有 `kind = plugin-residue` 的条目可以转成初始记忆；撤销不限制类型。转换与撤销都在同一事务里更新审计行、lore 的 `constant` 与上下文包缓存。
- 体检 token 两侧都只算真正导入成 lore 的条目，且排除 `memory = 1` 的条目；`before` 是原样模式的常驻全文，`after` 是升级模式的常识全文加实体索引。估算不调用模型、不落盘。
- `PATCH .../import-audit/entries/:source` 与 `PUT .../entries/:source/memory` 的 `source` 含冒号，客户端必须 `encodeURIComponent`；`kindSource` 只接受 `player` 与 `rule`，`model` 只能由后台任务写。
- 世界书槽位在导入过的故事里 Trace 来源带「升级」或「原样」前缀，没有审计行的故事保持 `lore:常驻 N 条、检索 M 条`；改这个字符串时要同步 `packages/st-compat/test/chat-cli.test.ts`。
- 升级模式不注入状态定义、条件内容、事件与舞台、写作指令、表现资源、作者选项、插件残留与未识别条目；这些类型的消费者分别是 W3-T03、W4、W6、W9，不要在 W3-T02 里临时把它们塞回世界书段。
- `import_kind` 的 `needsRun` 只看 `kind = unknown` 且 `kind_source = rule` 的条目；模型回复 `unknown` 时也记 `kind_source = model`，因此不会因同一条目反复入队。
- `import_kind` 每轮最多 320 条（40 条 × 8 批），剩下的由下一次 drain 继续；响应里出现本批之外的来源或重复来源整批拒绝，任务按框架重试；送进提示词的正文截到 800 字。
- 世界书分型的 `counts` 是每类命中数，一个条目可计入多类，不要求和等于条目数；要条目数用 `entries.length`。`primaryKind` 按 `IMPORT_ENTRY_KINDS` 顺序取第一个命中，`unknown` 排最后。
- 分型的规则只用标题与内容里的字面标记；沙箱实测未识别 19.5%，主体是 YAML 式章节回顾与文风指南。不要为了压低未识别率把这些标题词直接映射成实体，归 `unknown` 交给 `import_kind` 与玩家判定。
- 世界书分型是纯函数：不读磁盘、不调用模型、不改写入参；测试只用 fixture，不要拿沙箱条目写断言（I10）。
- `st-content` 的世界书激活（`activateStWorldInfo`、深度注入、计时效果）只在共存评测里使用；server 运行时没有接入，原样模式不是完整酒馆语义（ADR-0141、W3-T02.e）。

- 显示状态只在当前会话；需要跨进程显示时由台账快照重新渲染。
- 共存适配器在 `apply` 之后按轮调用 `afterTurn`；插件写错直接让运行失败。
- 共存评测的关闭组：适配器提供 `baseline` 时用 `<runDir>/<pluginId>/off`；不提供时用 `<runDir>/baseline/off`。
- `st-helper-host` 的共存批次不执行脚本：Node 里没有 iframe。
- EJS 模板里再写 `<%` 会被外层标签解析截断：内层模板通过变量或 `evalTemplate` 的第二参数传入。
- `st-ejs` 的激活正则默认一次性生效；注入标记与 `@INJECT` 必须独占一行才会被识别。
- 沙箱里模板函数是同步的；函数参数与返回值必须能 JSON 化；`define` 只在一次执行内有效，`include` 不可用。
- 回合预算只从调用方传进来：槽位提供者用 `request.budget`，直接调用运行时用 `render(text, { budget })`。
- `StEjsVariableStore` 接入 `backend` 后，不指定作用域的写进入 `initial`（台账 `mvu`）。
- 模板生成只登记请求：`generate` 返回 id 不返回正文，宿主用 `createStEjsBackgroundGenerationRunner` 接后台客户端并在间隙 `drain`。
- 酒馆助手的沙箱 API 全部异步；事件监听用整数 token；超时由宿主 `sweepTimeouts()` 驱动。
- STscript：`triggerSlash` 只执行 `ST_HELPER_SLASH_COMMANDS` 里的命令；变量命令默认作用域与上游一致；`/gen` 与 `/genraw` 只登记后台请求。
- HTML 状态栏与开场页的渲染结果只在插件显示状态；状态栏自动重渲染由变量写入触发，默认上限 8 次。
- 酒馆助手的 API 覆盖率快照以本机 JS-Slash-Runner 4.8.10 为准；升级上游版本时要重新生成名字清单。
- 助手任务不要复用 `turn_runs`；助手运行状态与事件在 `assistant_conversations`、`assistant_events` 里。
- 助手接口的请求与响应类型放在 `packages/protocol`；助手并发启动有 server 与 store 两层保护；提案工具对所有会话注入，靠白名单过滤。
- `assistant_actions` 的待定唯一索引以规范化 JSON 载荷为键；批准顺序是先校验、再调用领域写入、最后改状态。
- 技能注册表以 `packages/core/src/assistant/skills.ts` 为唯一来源；技能白名单里的工具名必须在本次运行实际注册。
- `AssistantDocsIndex.load` 每次 `startServer` 都会读取并切分文档（约 1.6 MB）。
- `summarize_recent` 只读现有压缩与摘要；联网搜索只由 `--assistant-web-search` 开启。
- 渠道读取不返回密钥值；`propose_channels_change` 四个段必须给全。
- 抽屉的持久状态只有 localStorage 里的活动会话 id；重连轮询必须在改状态之前把会话详情与消息写入状态。
- 压缩记录只追加；自动压缩在 server 的消息接口里执行；压缩失败的自动运行仍然返回模型回答。
- 待确认数量与待确认视图必须同源：`refreshPendingActions` 同时读动作与变更卡。
- 审阅面板的渠道字段只能渲染白名单字段；e2e 的审阅种子按 Playwright 项目名分开。
- web 源码不能 import `@dramaticer/core` 的运行时值（会把 `better-sqlite3` 与 `node:*` 打进前端包导致整页白屏），类型导入可以；助手类型从 `@dramaticer/protocol` 取。
- 上下文排布的设置只对内置默认模板生效；故事指向库里保存的模板时，`detectContextLayout` 记 `custom`，不要用 `contextLayout` 改写自定义模板。
- 旧的 Trace 没有 `cache`、`layout`、`segmentOrder`；读取方必须允许缺字段（`explain` 显示「没有记录」）。
- 导入体检页的「全部条目」是玩家改过类型后的恢复入口：未识别、作者选项、插件残留三组只按生效类型分组，条目改了类型就会离开原组；恢复规则判定只能从「全部条目」点。
- e2e 的 `pagination.spec.ts` 不要用 `scrollHeight` 在最后一页继续增长判断加载：虚拟列表在全部楼层加载后会把估算高度换成实测高度，总高度会回落；最后一页检查 `chat-load-older` 消失与最早楼层可见。
- 移动端故事导航是固定 9 列栅格（聊天、导入、体检、分支、台账、导演、生图、设置、渠道）；新增 tab 时同步改 `styles.css` 的 `repeat(9, …)` 与 `StoryPage` 的 `TABS`。
