# v3 设计提案（2026-11-07）

> 依据：`docs/dev/reports/F0.md` 的 F0-T99 节与 ADR-0043。输入：`docs/proposals/v3-review.md`（A 设计修订、B 路线修订）、`docs/proposals/plugins.md`、`docs/proposals/st-compat-plugins.md`。
> 本提案只确定主菜排序、优先级与阶段顺序。目标、范围与不变量保持 DESIGN v0.2 的写法，范围不得小于 v2、v2.1、v2.2 与两份插件提案。

## 一、数据给出的三条结论

| 结论 | 数字 |
|---|---|
| 与上下文容量直接相关的遗忘不是主因 | 「遗忘或前后矛盾」占主因 5.6%、次因 2.1% |
| 玩家不满意集中在开局 | 「不推进剧情」19.3% 与「没听用户的指示」18.2%，两者在 1–10 楼各占 25.0%；1–10 楼重 roll 率 24.9%，11 楼以后 7.0%–10.3%；楼层 ≤ 10 的 180 个对话里 62 个（34.4%）以一次重 roll 结束 |
| 输出形态与长度是第二类原因 | 「格式或状态栏」13.7%（次因 26.7%）、「截断」13.0%；助手回复 token P50 2,338 是旧默认 `maxTokens` 1024 的 2.3 倍；选项与交互输入开标签 1,965 次、图片块开标签 2,615 次 |

限制：归因模型只看最近 8 条消息，没有角色卡、世界书与台账，长程遗忘被低估；「其他」16.1% 未进一步归因。全文直接塞进上下文在容量上够用（95.1% 的对话放得下 128K），但楼层 ≥ 100 的 13 个对话里只有 1 个放得下，且全文组只有 8 次判断、同模型自评。裁判聚合一致率 73.3%，1–10 楼子集 61.4%、切回较早 swipe 的子集 55.2%，单次判断不可用。

## 二、主菜排序（别人做不到的体验）

1. **开局与方向。** 开场导演、首楼多候选、前 10 楼导演强度、用户意志捕获。依据是开局重 roll 率与 1–10 楼的两个主因各占 25.0%。
2. **输出形态。** 生成长度默认值、块的 prompt 视图、块的显示（选项、图片、状态栏）。依据是截断 13.0%、格式或状态栏 13.7% 及其 26.7% 的次因占比。
3. **记忆与台账最小集。** 结算器、现场分析、批量事件抽取、`gap_pass`、上下文包。依据是遗忘只占 5.6%，而楼层 ≥ 100 的对话有 13 个、≥ 200 的有 6 个，长对话仍需可用。
4. **生图。** 85.7% 的对话带生图插件元数据，第一批（ComfyUI 与 `illustrate` 块显示）排到最小界面之后。

父子分块、重排序、八段式压缩与世界书预筛保留全部任务，排在最小界面与长对话评测之后；由评测证据决定先后与默认开关，不删除。

## 三、开局与方向怎么做

| 机制 | 做法 | 约束 |
|---|---|---|
| 开局包 | 故事创建或导入后，后台用卡、世界书与玩家开场白生成开场地点与时间、在场人物与各自当下想要什么、第一个可行动冲突、三条可选开场方向；存成故事级记录 | 玩家首次输入之前完成；回合内不调用模型（I11） |
| 前 10 楼导演强度 | 导演配置按楼层深度分档，前 `openingFloors`（默认 10）楼用更高强度，指令具体到人和事 | 实时选择仍是纯程序（I9） |
| 首楼多候选 | 后台一次生成 2–3 个开场候选；玩家选一个，成为当前路径的第一个助手楼层，其余保留但不进入路径 | 不在回合内生成，不增加主调用；候选可重新生成 |
| 用户意志捕获 | R1-T07：从玩家消息识别偏好、底线与纠正，进入台账并永远优先 | 模糊陈述与角色台词不捕获 |

验收：同一批开局在开启与关闭开局机制下各跑自动试玩，比较 1–10 楼重 roll 率、指令遵循率与候选采用率；重 roll 率以 F0 的 24.9% 为对照基线。

## 四、输出形态

- **生成长度**：故事设置 `maxTokens` 默认取 `min(4096, writer 模型声明的上限)`；截断检测进 Trace，试玩与记分牌统计截断率。
- **块的 prompt 视图**：历史槽位按块的上下文策略渲染，显示类块（状态栏、变量更新、分析、选项、图片）在历史里省略，最近一楼保留完整原文；Trace 记录每种块被省略的字符与 token；原文不动（I8）。开关关闭时与现在逐字节一致。
- **块的显示**：最小界面必须显示选项块（点击填入输入框）与图片块；状态栏用原生组件渲染，不执行脚本。
- **块格式说明**：原生模板提供可选的 `block_format` 段，只说明格式，不要求模型输出（I13）。

## 五、记忆与台账最小集

- 结算器（R1-T02）：先解析本楼已有的结构化写入，再只对缺失路径调用模型；写入经校验与修复，冲突不覆盖。
- 现场分析（R1-T02.a）与 `gap_pass`（R1-T07.b）：间隙里合并为一次结构化调用，下一轮要用的优先。
- 批量事件抽取（R1-T03）：一次请求处理一个窗口，减少请求数。
- 上下文包（R1-T08）：同一玩家楼层的 swipe 与重新生成复用检索、预筛与分析结果。
- 记忆增强（父子分块、重排序、八段式压缩、世界书预筛）：全部任务保留，排在最小界面与长对话评测之后。

## 六、偏好信号

| 信号 | 强度 | 记录方式 |
|---|---|---|
| 重 roll（新建 swipe） | 强 | `preference_events`：被放弃节点 id、被接受节点 id、楼层、时间 |
| 选项块的选择 | 强 | 同上：选项正文与所在楼层 |
| 变更卡的批准或拒绝 | 强 | 同上：卡片 id 与决定 |
| 编辑 | 弱 | 同上：改前与改后的节点对；只作辅助信号，不单独用于胜负判断 |

- 记录只追加，带故事 id、节点 id、种类与载荷；属于私有数据，只能留在 `eval-private/` 与本地库，报告只出聚合数字。
- 评测用法：接受与放弃的回复对组成偏好测试集，用同一写作模型对两种 profile 重新生成，比较与玩家选择的一致率；裁判只用于扩展聚合样本（F0 的聚合一致率 73.3%），单次判断不用于偏好；切回较早 swipe 的子集单列，不并入总体一致率。

## 七、评测与自动试玩

- 原路线里的人类试玩全部换成自动试玩加评测：CLI 试玩（R2-T02）与界面试玩（R5-T13/T14），模拟用户由模型生成，报告分私有版与统计版，门槛在运行前写进报告。
- 主对照是同一写作模型下的 B0 与 native；B1 历史回放标出历史回复所用模型，找不到同模型样本时只作参考。
- 公开合成基准在 R2 建立，用 SFW 或合成卡，和项目一起发布；3 个私有对话不足以支撑门槛判断。
- 裁判换不同模型家族的模型并重新校准；`judge` 与 `writer` 由路由创建时校验（R1-T01.b）。
- 长对话遗忘评测（R2-T09）给出「遗忘是否随楼层加深而上升」的证据，作为记忆增强的输入。

## 八、插件与 ST 兼容

- `docs/proposals/plugins.md` 全部采纳：Context 与插件注册表、扩展点与分发模式、两档插件、玩法包与卡片依赖、插件市场；对外只暴露 Dramaticer 自己的类型；内置模块也按插件实现。
- ST 兼容不做放弃清单：四个插件 `st-content`、`st-mvu`、`st-ejs`、`st-helper-host` 全部实现，顺序 P-A → P-C → P-B → P-D；core 不出现 ST 概念（I1、I15）。
- 技术验证 P1 排在最小界面之后；内核改造 P2 排在 P1 之后且不早于 R5 完成，避免内置接口未稳定时抽象两遍；P3 与 P4 在 P2 与 R6 之后；P5（应用内插件市场）在公开 alpha 之后。
- 兼容插件用忠实模式做一致性比对、共存模式做开关对照评测，规则见 ADR-0040 与 ADR-0041 的 A10。

## 九、路线

| 阶段 | 产出 | 过关标准 |
|---|---|---|
| **R1 最小集** | 渠道按岗位、生成长度默认值、结算器、现场分析、块的 prompt 视图、用户意志、变更卡、`gap_pass`、批量事件抽取 | 回合内零后台调用；结算、模板与压缩测试通过；R1 最小集验收 |
| **R3 快回合** | 快回合循环、单轮与故事级模式开关、文本协议、写作契约 | 真实渠道 20 轮；工具轮数不超过软上限；程序不自动切换 |
| **O 开局与方向** | 开局包、开场导演与前 10 楼强度、首楼多候选 | 1–10 楼重 roll 率低于 24.9%；候选采用率有记录 |
| **R2 评测底座** | B0/B1、CLI 自动试玩、一致性探针、五类记忆题、盲测与质量评分、偏好信号、公开合成基准、长对话遗忘报告 | 对比数字可复现；门槛运行前登记 |
| **E 排障** | `dramaticer explain` | 零模型调用，结论带证据 |
| **R4 Director v2** | 弧线与序列、后台规划器、落拍、候选行动、注入 | 短线层零模型调用 |
| **R5 界面** | 最小界面（聊天、swipe、台账只读、图片与选项块、模式开关）、其余面板、Playwright、60 轮自动试玩 | 端到端通过；试玩报告齐全 |
| **M6 生图第一批** | ComfyUI 与 `illustrate` 块显示 | 出图挂到楼层节点 |
| **R1 续 记忆增强** | 父子分块、重排序、八段式压缩、世界书预筛、上下文包 | 由长对话评测证据决定先后与默认开关 |
| **R3b 深回合** | 单 agent 循环、草稿与提交、导演手记、原生元数据回放 | 失败率明显低于 23% |
| **P1 / P2** | 插件技术验证与内核改造 | 每改一个内置模块门禁与评测不退化 |
| **C 兼容插件** | `st-content`、`st-mvu`、`st-ejs`、`st-helper-host` | 一致性测试与共存评测 |
| **H 助手** | 抽屉与全部技能 | 与正剧隔离；影响剧情的修改走变更卡 |
| **X 实验** | 世界模型表示方式、Director 组织方式 | 显著胜出才切换 |
| **R6 效果门槛** | 对 B0 与 B1 达标 | 赢过基线；没赢就自动改进并重评，最多三轮 |
| **P3 / P4** | 声明式插件格式、代码插件（权限清单与隔离） | 权限清单与沙箱隔离 |
| **M5 公开 alpha** | 发布材料与安装包 | 由 M5-T00 细化 |
| **P5** | 应用内插件市场 | 由 R0-T04 建立的任务细化 |
| **M7 Tauri** | 桌面与移动打包 | 由 M7-T00 细化 |
