## 二、核心判断

1. 真实的卡是用世界书写成的应用程序，不是设定集。导入必须按条目的运行时行为分流。
2. 真实的玩家近五分之一的输入是「推进」。方向必须由系统供给，但玩家写了具体内容时系统要让位。
3. 模型近一半的输出在做记账。这些工作全部移到后台，正文只写故事。
4. 运行时的基本单位应当是**场次**，不是楼层。场次结束才是事实稳定、值得归档的时刻。

## 三、运行时：场记、档案、导演

### 3.1 场记（每楼一次小调用）

回复落定后在间隙里做一次输出很短的后台调用，记四样东西：本楼的节拍标签（安抚、试探、冲突升级、揭示……）；硬状态变化（位置、衣着、伤势、持有物、时间、卡定义的变量）；在场者；这一场是否结束。同一次调用顺带判断剧情小品与条件内容里的文本条件。

- 它取代现在分开运行的结算、现场分析、用户意志捕获与小品条件判断。
- 硬状态要少而准，只保留写下一楼必须对得上的项。性格变化、关系史这类软知识不进结构，由档案用文字记。
- **每条事实带原文引文**：`sourceQuote` 必须逐字出自源楼层，由程序校验，对不上就拒绝。这是把现有用户意志与变更卡的做法推广到全部结算事实，是 I12 校验路径的加强。

### 3.2 档案（场次结束时归档）

一场结束时做一次归档调用：这一场的摘要、在场者、状态变化、开了和收了哪些线索；随后更新涉及人物的个人档案。

- **知情由在场推导**：一个角色知道某件事，当且仅当他在那一场，或者之后有一场里被告知。不再单独维护逐条的知情表。
- **对模型是标注，不是过滤**：写作模型一个人演所有角色，必须知道全部真相。注入时写明「这件事某某不在场、不知情」。DESIGN §7.3 的「知情者过滤」改为「知情标注」。
- **重逢注入是记忆的主路径**：人物、地点或物品在最近窗口里没有出现、现在被提到或被导演安排登场时，由程序按名字与别名触发，注入它的档案（上次出场的场次、当时的关系、未了结的事）。全文检索降为兜底与主动查询工具。
- **按需付费**：全文放得下预算时不做归档与检索；开始超出时对即将滑出窗口的场次成批归档；几百楼以上再开检索。

### 3.3 场次边界

由场记判定，加楼层数上限兜底（默认 12 楼强制切一场）。边界判错会导致归档过碎或过粗，这是整套方案的地基，必须最先验证。

## 四、上下文布局与成本

- 现状（`packages/core/src/chat/template.ts` 的原生模板）：世界书、摘要、检索记忆、现场分析、导演、用户意志都排在历史之前。检索记忆与现场分析每轮都变，历史每轮都无法命中前缀缓存。
- 改为按易变性排布：卡与常驻设定 → 只追加的章节档案 → 历史原文 → 每轮变化的槽位（状态、重逢档案、场面卡、导演）→ 玩家消息 → 写作契约。
- DESIGN §9「不在缓存统计上投入精力」改为：渠道体检检测是否透传缓存；Trace 记录缓存命中的 token；界面显示每轮成本。
- 后台调用的目标形态：每楼一次场记，每场一次归档，每章一次规划。

## 五、世界包与分型导入

### 5.1 条目按运行时行为分型

| 类型 | 真实卡里的样子 | 运行时行为 |
|---|---|---|
| 常识 | 世界观总览、核心设定 | 很短，常驻，排在最前 |
| 实体档案 | 人物、地点、势力、物品，以及卡特有的实体 | 索引常驻，详情在出场或被提到时注入；人物随剧情更新，地点不变 |
| 规则 | 境界、战斗、玩法、声望 | 相关情境出现时注入对应条目；能计算的部分由程序执行 |
| 状态定义 | 变量列表、初始值、更新规则 | 成为原生状态表；更新由场记完成 |
| 条件内容 | 读变量后做条件判断的阶段性设定 | 条目加「何时生效」条件，复用模板条件语言 |
| 事件与舞台 | 章节舞台、动态事件、随机事件 | 交给导演，成为线与小品 |
| 写作指令 | 思维链、元指令、格式要求、文风 | 独立的文风层，可整体开关 |
| 表现资源 | 插画表、背景音乐、状态栏模板 | 资源表，按场景匹配，由程序渲染 |
| 作者选项 | 可选、扩展、难度、模式 | 生成选项面板 |
| 插件残留 | 表格、总结条目 | 导入为初始记忆，或丢弃 |

一个条目可以有多个类型。混合条目不拆分原文。

### 5.2 升级向导

1. 程序规则先分型（标题前缀、内容标记）；拿不准的交给后台模型；单纯的名字默认归实体。
2. 人物条目提升为人物档案：想要什么、瞒着什么、说话样本。事件条目提升为线。
3. 导入后给一页**体检结果**：各类型的条数、每轮常驻 token 的前后对比、未识别条目；一键接受或逐类调整。
4. 每张卡一个总开关：**升级模式**或**原样模式**。原样模式用现有兼容插件按酒馆的方式运行。

### 5.3 规则层

DESIGN §18 的「程序化检定工具」从暂缓提到这一阶段：状态表、检定、资源扣减由程序执行，模型叙述结果。只把能确定计算的规则结构化，其余保留为文字约束。

## 六、导演与剧情规划

### 6.1 规划局面，不规划剧本

「弧线加序列加节拍游标」改为一组**线**。每条线的字段：谁想要什么；阻碍与代价；倒计时（按故事时间自己推进）；后台预备的两三种发展；冷热（上次被触及的楼层）。种类：主线问题、人物关系线、对手的图谋、伏笔与约定。卡里的章节舞台、动态事件与条件内容导入为线及其触发条件。

### 6.2 三个时间尺度

| 尺度 | 何时 | 用什么 | 产出 |
|---|---|---|---|
| 章 | 章节结束 | 一次后台调用，可配置更强的模型 | 清点所有线：收掉、作废、新开；确定下一章聚焦的两三条线 |
| 场 | 新场景开始 | 并入场记调用 | 场面卡：在场者各自想要什么，这一场结束时应该改变什么 |
| 拍 | 每一轮 | 纯程序，零调用 | 选一个动作 |

### 6.3 八种动作

程序决定做哪种动作，剧情小品提供具体内容。两者是两层，不再是二选一。

| 动作 | 触发条件（全部由程序判断） |
|---|---|
| 让位 | 玩家写了具体指示 |
| 接球 | 场面目标未达成 |
| 加码 | 场面过于顺利，从某条线取一个阻碍 |
| 闯入 | 某条线的倒计时到点 |
| 兑现 | 有伏笔足够老，且当前场景能接上 |
| 揭示 | 在场人物持有与当前话题相关的秘密 |
| 喘息 | 连续几楼高强度之后 |
| 转场 | 场面目标已达成，或连续几楼没有任何状态变化 |

输入是场记的记录：最近几楼的节拍、状态变化、各条线的冷热与倒计时、最近用过的动作。同一动作不连用三次。每次选择的理由写进 Trace，`explain` 可查。重复检测改为读节拍标签；最近几楼的节拍以「刚做过的事」告知写作模型。

### 6.4 「推进」的三档语义

| 档位 | 含义 |
|---|---|
| 推进 | 在当前场景里接球或加码 |
| 快速推进 | 让这一场达成目标并转场 |
| 大幅推进 | 跳到下一个倒计时到点的时刻，中间几句带过；导演给出目的地 |

### 6.5 伏笔账

未兑现伏笔设上限（默认 5），满了不再鼓励开新的；越老「兑现」的优先级越高；章末清点时对每条旧伏笔明确处理：安排到下一章，或作废。

### 6.6 建议写成局面

注入写作模型的是世界里的事实加人物意图（「此刻门外，某某已经到了，她是来要回那封信的」），不是写作指令。附带现有的「玩家行动优先」说明。

### 6.7 玩家在线这一层参与

- 章末三选一：前情提要加三个下一章方向，或「让它自己走」。复用开局包机制。
- 导演台：列出线与倒计时；可以置顶、静音、新增。透明与盲盒两种模式保留。

## 七、故事蓝图

玩家与 AI 共同维护的长线大纲，整体可选。

- **结构**：总纲（核心问题、基调、候选结局、红线）→ 卷（核心问题、起止状态）→ 里程碑（希望发生的事、前提条件、先后约束、硬性或软性）。里程碑不绑定楼层。远粗近细：只有下一章展开到场面级别。
- **AI 完善**：玩家用自然语言写，AI 返回可逐条接受或拒绝的建议：结构化、补铺垫、对照已发生剧情与设定查矛盾、最多两三个反问。操作：帮我补全、找漏洞、给三种走向、展开这一卷、按最近剧情更新。
- **保护玩家的文字**：每条标明出处（玩家写的、AI 补的）；玩家可以锁定任何一条；AI 的修改只以建议形式出现。
- **影响游玩**：里程碑需要的铺垫进入伏笔账，成为导演的待办；章级规划以最近的里程碑为准；写作模型只看到当前卷的问题、最近一个里程碑的方向与本章该埋的线，完整蓝图只留在导演层；拉力三档（松、中、紧），任何档位下玩家当轮的行动优先。
- **偏离处理**：每章结束检查里程碑状态（已达成、仍可达、受阻、已不可能）。受阻或不可能时给玩家三个选择：调整蓝图、把剧情拉回、放弃。系统不自动改写。
- **版本**：修改按楼层记录、沿路径累加，与导演手记同一做法；分支各有版本，可回看与回滚。
- **剧透选项**：AI 补的部分可以对玩家隐藏，只显示数量。
- **来源与分享**：卡里的章节舞台导入为默认蓝图；蓝图可随世界包导出。

## 八、交互

- **输入区**：「推进」主按钮加三档强度；行动选项以按钮呈现，点击填入、可改；自由输入照常；候选行动里固定一项「让故事自己走」。
- **带原因的重 roll**：重 roll 时可选原因（没推进、没听我的、太短、人设不对、格式乱、别推这条线），下一次生成带着这条纠正；原因写入偏好信号。
- **就地纠正**：选中一段指出问题，重写该段，并记为用户意志。
- **场面控制**：结束这一场、跳到某个时间、调整节奏。
- **正文区**：正文按书页排版；场记的记录（状态变化、伏笔的埋与收、本轮导演动作）以页边批注显示，可关闭。
- **连载视图**：前情提要（隔一段时间回来时显示）、章节目录、人物关系页、时间线、可编辑的记忆、导出成书。
- **每轮成本**：输入、输出、缓存命中率与后台开销显示在输入区下方。
- **卡面图**：角色卡自带的图片（卡片 PNG 本身）作为故事的封面，显示在书架、游玩页标题旁与导入体检页；卡里表现资源表提供的人物立绘显示在人物档案上。图片只读取、不改写，经认证的媒体接口提供；没有图片的卡用按标题生成的占位图。现状：server 与 web 都还没有读取卡面图。

## 九、功能开关

三层，避免旋钮泛滥：

1. **档位**：轻量、标准、沉浸，一键切换。
2. **功能开关页**：按玩家能感知的效果分组；每个开关一句话说明，并显示两个实测数字（每轮花多少、在这个故事里起过多少次作用）。
3. **本轮临时开关**：在输入框旁，只对这一轮生效。

开关清单：场记、档案归档、重逢注入、全文检索、导演（关闭、仅在按推进时、始终）、知情标注、伏笔上限、规则执行、状态面板、行动选项、出图（手动、按章提名、模型主动）、背景音乐、思考档位、工具查阅、写作指令层、原样兼容。卡的作者选项单独一页。默认值按卡自动判断，卡里没有的能力不显示对应开关。

因为原文不可变、视图全部派生，**任何功能都可以中途开关并追溯补算**。这一点写进产品说明。

## 十、其他取舍

- **输出只要正文**：状态栏、选项、图片、变量更新都由程序根据状态渲染或由后台完成，不要求模型输出。
- **插图**：场次归档时由后台提名 0 到若干个「值得画的瞬间」，数量由剧情决定；玩家设置的频率只作为每章上限；保留手动与模型主动触发。
- **工具**：不把多轮调用当成默认更好。默认回合是一次调用加思考；工具按用途开放——卡声明了规则时开放检定工具，设定库超过规模且渠道体检确认模型会用工具时开放查阅，出图按设置。完整的自主循环（深回合）保留为可选功能，不作为发布门槛。
- **人物声音卡**：每个主要人物一份说话样本，只在在场时注入，可从玩家接受过的楼层补充。
- **一分钟开玩**：导入卡、选渠道、进入开场候选；预设降为可选的文风。
- **暂不投入**：插件市场、加深酒馆脚本模拟、新的记忆表示方式、多 agent 讨论。

## 十一、与现有设计的冲突

| 事实 | 数字 |
|---|---|

结论：深回合零工具调用是因为循环没有给模型用工具的理由（直接输出会被接住、信息已全部预先注入、没有定义改稿、没有技能提供检查标准），不是 flash 级模型不会用工具。ADR-0055（合并调用的准确率低于四个独立任务）同样说明拆分对 flash 级模型有利。

### 14.2 回合模式：三种，改名

| 新名字 | 原名 | 做法 | 适合 |
|---|---|---|---|
| **快速模式** | 快回合 | 一次主调用，写一遍就交 | 强模型，或想省调用的时候 |
| **规划模式** | （新增） | 程序规定的固定阶段，先理清再写；阶段尽量在间隙里预先完成 | flash 级模型的默认推荐 |
| **深度模式** | 深回合 | 起草、自检、修改、提交的草稿工作区循环 | 愿意等、要最细的一楼 |

- 三种模式只由玩家手动切换；界面可以按渠道体检的结果给出推荐，不自动切换。
- 这是界面与文档里的名字。代码标识符是否跟着改由实现任务决定，不为改名单独动存储结构。

### 14.3 规划模式：固定阶段加间隙预跑

| 阶段 | 做什么 | 何时运行 |
|---|---|---|
| 状态整理 | 场记已经完成 | 间隙 |
| 挑记忆与规则 | 把档案索引与规则列表摆出来，让模型挑本轮相关的；程序触发的重逢注入作为保底 | 对可预测的输入在间隙；自由输入在回合内 |
| 角色各自出招 | 每个在场角色只凭自己知情范围内的事提出想做什么 | 间隙，并入场面卡 |
| 本轮计划 | 结合玩家输入与导演选的动作，定这一楼要发生什么 | 同第二项 |
| 正文 | 主调用 | 回合内 |
| 复查（可选） | 检查状态矛盾与串戏；结果存成可切换的回复版本（兄弟节点） | 正文之后，不阻塞显示 |

- **间隙预跑**：回复落定后，对「推进」三档与每个行动选项分别把准备阶段跑完。依据是约 18% 的玩家输入是推进类、给出选项后 83% 的回复不超过 40 字符。命中预跑时回合内只剩正文调用；自由输入时在回合内跑准备阶段并显示进度。
- 预跑会有浪费，做成开关，默认只在「沉浸」档开启。「推进」的正文也预先生成是可选项，单独一个开关。
- 仍然不做的只有一种：多个 agent 之间来回讨论。

### 14.4 深度模式：草稿工作区循环

- 回复是工作区里的一个草稿文件。工具只有少数几个通用的：读、搜、写、打补丁、提交、结束。
- **故事数据呈现为文件树**：人物档案、章节摘要、蓝图、导演手记都是文本文件，用同一组工具访问；对它们的修改照常变成变更卡。存储仍是数据库与沿路径的版本。
- **自检清单由程序给出**：在场人物的位置、衣着、伤势；谁不在场、不知情；最近几楼的节拍；玩家的长期要求；这一章该埋的铺垫。
- **文风与规则作为技能**：卡或预设自带的技能包，自检时按需读取。
- 模型不走流程、直接输出正文时照常接住并成为楼层。
- 草稿实时显示；对可预测的输入可以在间隙预跑。
- 验收对照 TauriTavern 的记录：工具调用率大于 0，失败率明显低于 23%。

### 14.5 来自预设：原生写作设置

把玩家反复在预设里选的事做成少量明确的选项：文风、人称、字数、节奏、是否替玩家行动、尺度、思考方式。导入预设时把能对应的条目映射到选项上，其余作为可整体开关的文风包；思维链类条目的作用由场面卡、导演的局面注入与模型自带思考承担。

## 十五、增补：玩家可以自由修改一切（2026-11-14，人类要求）

原则：**系统知道的每一样东西，玩家都能看到、能改、能撤销。** 唯一不能改的是楼层原文（I4）；想改正文用现有的编辑，它新建兄弟节点。

现状（2026-11-14 核对 server 接口）：蓝图与导演计划可读写；台账只读，修改只能走变更卡；世界书条目、章节档案、人物档案、摘要与事件没有任何编辑接口。

### 15.1 三类数据，三种编辑语义

| 类别 | 包含 | 编辑语义 |
|---|---|---|
| 作者内容 | 世界书条目、人物设定、规则、写作设置、作者选项、表现资源 | 改的是**这个故事的副本**（第 14.6 的资源快照）；不影响卡库与其他故事；可以「恢复成卡的原样」「存回卡库」「导出成新卡」 |
| 系统记下的 | 硬状态、人物档案、章节与场次摘要、事件、知情、用户意志 | 直接改，立即生效；记为来源 `player` 的修改，重算与补算不得覆盖 |
| 规划 | 线与倒计时、伏笔账、场面卡、蓝图、章末方向 | 直接改；蓝图已有的出处与锁定规则推广到全部规划对象 |

### 15.2 共同规则

- **玩家自己的修改不需要批准。** 变更卡只用于 AI 提出的修改。玩家的修改经过同一套格式校验后直接写入（I12 不变：写入仍经过结算器的校验），校验失败在原处提示原因。
- **出处与锁定。** 每一项都标明来源（卡、AI、玩家）。玩家改过的项自动锁定：后台任务与 AI 只能对它提建议，不能覆盖。玩家可以解锁。
- **玩家的修改优先于原文推断。** 结算与冲突检查不得因为「与最近楼层原文矛盾」而撤销来源为 `player` 的事实；只有之后的楼层明确写出了变化，才产生新的变更，并保留玩家那一条的历史。
- **沿楼层树记录。** 修改挂在当前楼层上、沿路径累加：默认从当前楼起生效，之前的分支不受影响，切换分支得到各自的版本；每一项都有修改历史、差异对比与回滚。
- **删除是「不再使用」。** 记忆与设定的删除标记为停用，可以恢复；不做物理删除。
- **生效时机可见。** 修改后提示「下一轮生效」；世界书条目提供「这一条什么时候会被带入」的预览（类型、条件、当前是否命中）。

### 15.3 入口

- 每个面板就地编辑：档案、目录、导演台、蓝图、设定库。
- **从「本轮注入了什么」直接改**：点任何一条被注入的内容，跳到它的来源并修改。这是「为什么它这么写」到「把它改对」的最短路径。
- 用自然语言让助手改：助手生成的修改照旧走变更卡。
- 文件方式：第 14.4 的文件树可以整体导出、在外部编辑器里修改后导回；导回时逐项显示差异，由玩家确认。
- 设定库的批量操作：按类型筛选、批量启停、改类型、改生效条件、新建与复制条目。

## 十六、记忆层定稿（2026-11-14，人类已确认）

参考：Letta（常驻核心记忆、后台整理、文件加简单工具）、Mem0 2026 年 4 月的新算法（只新增、实体做索引、三路融合检索、按时间解决新旧）、Zep（变化不覆盖）、LongMemEval（整理出的事实当索引、取回原文）、生成式智能体（重要度与反思）。只借鉴做法，不引入依赖。**与第三节、第十五节冲突时以本节为准。**名字按 `GLOSSARY.md`。

### 16.1 三层

| 层 | 内容 | 性质 |
|---|---|---|
| 原文 | 全部楼层，不可修改 | 唯一的真相 |
| 整理过的知识 | 记录、状态、秘密、百科、时间线、偏好 | 都带原文出处，可改、可重建 |
| 上下文 | 这一轮实际带入的部分 | 每轮按规则组装，玩家看得见 |

### 16.2 整理过的知识

- **记录**：只追加。每条是一句独立的事实或事件，带楼层、故事时间、涉及的实体、重要度、逐字出处。后台模型只写新记录，不改、不删旧的；新旧说法都保留，读取时按时间解决。现有的事件索引升格为它，结算产生的事实也以记录的形式追加。
- **状态**：位置、衣着、伤势、持有物、时间、卡定义的数值。由程序从记录里按键取最新值，是确定性的投影。卡可以声明自己的类型，各带抽取频率与是否常驻。
- **秘密**：是什么、谁知道、谁不知道。在场即知道；转述、偷听、书信由自动记录显式标出「某人得知某事」。
- **百科**：人物、地点、势力、物品、剧情线的页面，**由该实体的全部记录汇编而成**，不是后台模型直接改写的对象。语句带出处与有效范围（「至第二章」）。汇编错了重新汇编即可。
- **时间线**：场次摘要汇成章，章汇成卷。只追加，每一级都能展开到原文。
- **偏好**：玩家的偏好、底线、纠正，以及重写时选的原因。

### 16.3 写入（全部在间隙）

1. 每楼：自动记录一次调用，追加若干记录并给出状态变化；转折、揭秘、承诺、首次出场标为重要。
2. 每场结束：追加场次摘要；更新秘密。
3. 每章结束：追加章节摘要；做一次反思（谁变了、哪段关系的性质变了），结果同样作为带出处的记录；重新汇编涉及实体的百科页。
4. 玩家纠正或重写带原因：写入偏好。
5. 故事还放得下上下文时，第 2、3 步不做。

### 16.4 读取（按这个顺序排进上下文）

1. 偏好、故事索引、时间线（稳定，利于缓存）。
2. 尽可能长的原文窗口。
3. 状态、秘密。
4. 在场人物与当前地点的百科页；从它们和活跃剧情线顺着链接走一步的页面摘要；重逢提醒。
5. 一次融合检索：语义、关键词、实体三路并行打分后融合，实体这一路由在场者与玩家提到的名字驱动，结果按故事时间排新旧。重要的记录带回原文摘录。
6. 可选：让模型从目录里再挑几页（功能开关）。
7. 规划与深度两种写法下，记忆呈现为文件树，配读、搜、打补丁三个工具。

### 16.5 防错

出处逐字校验；矛盾不覆盖，交给玩家裁决；玩家的修改记为来源为玩家、优先级最高的记录并锁定；每轮上下文可见、可跳转修改；任何一页可从原文重建。

### 16.6 不采用

外部记忆服务；用知识图谱做存储；每楼写摘要；让写作模型在回合内自己管理记忆；让后台模型更新或删除旧记录。

### 16.7 未验证

记录数量随楼层增长后的检索噪声；倒叙与回忆场景下按时间取用是否取错；flash 级模型汇编页面的质量；反思是否产生没有依据的结论。程序可判的指标是上下文充分性：评测题的答案是否出现在这一轮组装好的上下文里。

## 十七、导演不干扰玩家（2026-11-14，人类已确认）

原则：**导演只填补玩家留下的空白，不覆盖玩家的选择。**

### 17.1 已实现代码里的三处干扰（`packages/core/src/director/lines.ts`）

1. 用字数判断玩家有没有给方向：不少于 12 个字才算。短而明确的行动会被当成没给方向。本地聊天数据里 38% 的玩家消息不超过 10 个字。
2. 判定为不干预时，仍然把最热的剧情线写进注入内容。
3. 连续 2 楼没有状态变化就算「过于顺利」并加阻碍，玩家想安静地聊几楼也会被催。

### 17.2 规则

- **看内容不看字数。** 玩家输入分三类：推进（按了推进按钮，或消息属于「继续、推进剧情」这类固定说法）；点了行动选项；其他一切自由输入。只有第一类导演才出手，后两类一律不干预，不管多短。
- **不干预就是什么都不注入。** 导演槽位为空。
- **突发要等。** 剧情线到点时，如果玩家正在自己写，突发延后到下一次推进或这一场结束；只有标记为必须打断的事件可以打断，每一场最多一次。
- **节奏由玩家定。** 「过于顺利」只在推进时作为加阻碍的依据。
- **玩家的行动改写剧情线。** 玩家做的事可以让一条线提前了结、转向或作废，章末清点时据此重排。大纲同理：走偏时默认是大纲跟着改。
- **默认值。** 导演何时出手默认「仅推进时」；大纲约束默认「弱」。
- **可见、可撤。** 批注里的每条导演安排带「这不是我要的」：撤回、记入偏好、把对应的剧情线静音。

### 17.3 指标

重写原因里「没听我的」与「别推这条线」的比例，导演开启时不得高于关闭时。数据来自玩家的实际操作，不需要裁判。
