## 二、核心判断

1. 真实的卡是用世界书写成的应用程序，不是设定集。导入必须按条目的运行时行为分流。
2. 真实的玩家近五分之一的输入是「推进」。方向必须由系统供给，但玩家写了具体内容时系统要让位。
3. 模型近一半的输出在做记账。这些工作全部移到后台，正文只写故事。
4. 运行时的基本单位应当是**场次**，不是楼层。场次结束才是事实稳定、值得归档的时刻。

## 三、运行时：场记、档案、导演

### 3.1 场记（每楼一次小调用）

回复落定后在间隙里做一次输出很短的后台调用，记四样东西：本楼的节拍标签（安抚、试探、冲突升级、揭示……）；硬状态变化（位置、衣着、伤势、持有物、时间、卡定义的变量）；在场者；这一场是否结束。同一次调用顺带判断剧情小品与条件内容里的文本条件。

- 它取代现在分开运行的结算、现场分析、用户意志捕获与小品条件判断。
- 硬状态要少而准，只保留写下一楼必须对得上的项。性格变化、关系史这类软知识不进结构，由档案用文字记。
- **每条事实带原文引文**：`sourceQuote` 必须逐字出自源楼层，由程序校验，对不上就拒绝。这是把现有用户意志与变更卡的做法推广到全部结算事实，是 I12 校验路径的加强。

### 3.2 档案（场次结束时归档）

一场结束时做一次归档调用：这一场的摘要、在场者、状态变化、开了和收了哪些线索；随后更新涉及人物的个人档案。

- **知情由在场推导**：一个角色知道某件事，当且仅当他在那一场，或者之后有一场里被告知。不再单独维护逐条的知情表。
- **对模型是标注，不是过滤**：写作模型一个人演所有角色，必须知道全部真相。注入时写明「这件事某某不在场、不知情」。DESIGN §7.3 的「知情者过滤」改为「知情标注」。
- **重逢注入是记忆的主路径**：人物、地点或物品在最近窗口里没有出现、现在被提到或被导演安排登场时，由程序按名字与别名触发，注入它的档案（上次出场的场次、当时的关系、未了结的事）。全文检索降为兜底与主动查询工具。
- **按需付费**：全文放得下预算时不做归档与检索；开始超出时对即将滑出窗口的场次成批归档；几百楼以上再开检索。

### 3.3 场次边界

由场记判定，加楼层数上限兜底（默认 12 楼强制切一场）。边界判错会导致归档过碎或过粗，这是整套方案的地基，必须最先验证。

## 四、上下文布局与成本

- 现状（`packages/core/src/chat/template.ts` 的原生模板）：世界书、摘要、检索记忆、现场分析、导演、用户意志都排在历史之前。检索记忆与现场分析每轮都变，历史每轮都无法命中前缀缓存。
- 改为按易变性排布：卡与常驻设定 → 只追加的章节档案 → 历史原文 → 每轮变化的槽位（状态、重逢档案、场面卡、导演）→ 玩家消息 → 写作契约。
- DESIGN §9「不在缓存统计上投入精力」改为：渠道体检检测是否透传缓存；Trace 记录缓存命中的 token；界面显示每轮成本。
- 后台调用的目标形态：每楼一次场记，每场一次归档，每章一次规划。

## 五、世界包与分型导入

### 5.1 条目按运行时行为分型

| 类型 | 真实卡里的样子 | 运行时行为 |
|---|---|---|
| 常识 | 世界观总览、核心设定 | 很短，常驻，排在最前 |
| 实体档案 | 人物、地点、势力、物品，以及卡特有的实体 | 索引常驻，详情在出场或被提到时注入；人物随剧情更新，地点不变 |
| 规则 | 境界、战斗、玩法、声望 | 相关情境出现时注入对应条目；能计算的部分由程序执行 |
| 状态定义 | 变量列表、初始值、更新规则 | 成为原生状态表；更新由场记完成 |
| 条件内容 | 读变量后做条件判断的阶段性设定 | 条目加「何时生效」条件，复用模板条件语言 |
| 事件与舞台 | 章节舞台、动态事件、随机事件 | 交给导演，成为线与小品 |
| 写作指令 | 思维链、元指令、格式要求、文风 | 独立的文风层，可整体开关 |
| 表现资源 | 插画表、背景音乐、状态栏模板 | 资源表，按场景匹配，由程序渲染 |
| 作者选项 | 可选、扩展、难度、模式 | 生成选项面板 |
| 插件残留 | 表格、总结条目 | 导入为初始记忆，或丢弃 |

一个条目可以有多个类型。混合条目不拆分原文。

### 5.2 升级向导

1. 程序规则先分型（标题前缀、内容标记）；拿不准的交给后台模型；单纯的名字默认归实体。
2. 人物条目提升为人物档案：想要什么、瞒着什么、说话样本。事件条目提升为线。
3. 导入后给一页**体检结果**：各类型的条数、每轮常驻 token 的前后对比、未识别条目；一键接受或逐类调整。
4. 每张卡一个总开关：**升级模式**或**原样模式**。原样模式用现有兼容插件按酒馆的方式运行。

### 5.3 规则层

DESIGN §18 的「程序化检定工具」从暂缓提到这一阶段：状态表、检定、资源扣减由程序执行，模型叙述结果。只把能确定计算的规则结构化，其余保留为文字约束。

## 六、导演与剧情规划

### 6.1 规划局面，不规划剧本

「弧线加序列加节拍游标」改为一组**线**。每条线的字段：谁想要什么；阻碍与代价；倒计时（按故事时间自己推进）；后台预备的两三种发展；冷热（上次被触及的楼层）。种类：主线问题、人物关系线、对手的图谋、伏笔与约定。卡里的章节舞台、动态事件与条件内容导入为线及其触发条件。

### 6.2 三个时间尺度

| 尺度 | 何时 | 用什么 | 产出 |
|---|---|---|---|
| 章 | 章节结束 | 一次后台调用，可配置更强的模型 | 清点所有线：收掉、作废、新开；确定下一章聚焦的两三条线 |
| 场 | 新场景开始 | 并入场记调用 | 场面卡：在场者各自想要什么，这一场结束时应该改变什么 |
| 拍 | 每一轮 | 纯程序，零调用 | 选一个动作 |

### 6.3 八种动作

程序决定做哪种动作，剧情小品提供具体内容。两者是两层，不再是二选一。

| 动作 | 触发条件（全部由程序判断） |
|---|---|
| 让位 | 玩家写了具体指示 |
| 接球 | 场面目标未达成 |
| 加码 | 场面过于顺利，从某条线取一个阻碍 |
| 闯入 | 某条线的倒计时到点 |
| 兑现 | 有伏笔足够老，且当前场景能接上 |
| 揭示 | 在场人物持有与当前话题相关的秘密 |
| 喘息 | 连续几楼高强度之后 |
| 转场 | 场面目标已达成，或连续几楼没有任何状态变化 |

输入是场记的记录：最近几楼的节拍、状态变化、各条线的冷热与倒计时、最近用过的动作。同一动作不连用三次。每次选择的理由写进 Trace，`explain` 可查。重复检测改为读节拍标签；最近几楼的节拍以「刚做过的事」告知写作模型。

### 6.4 「推进」的三档语义

| 档位 | 含义 |
|---|---|
| 推进 | 在当前场景里接球或加码 |
| 快速推进 | 让这一场达成目标并转场 |
| 大幅推进 | 跳到下一个倒计时到点的时刻，中间几句带过；导演给出目的地 |

### 6.5 伏笔账

未兑现伏笔设上限（默认 5），满了不再鼓励开新的；越老「兑现」的优先级越高；章末清点时对每条旧伏笔明确处理：安排到下一章，或作废。

### 6.6 建议写成局面

注入写作模型的是世界里的事实加人物意图（「此刻门外，某某已经到了，她是来要回那封信的」），不是写作指令。附带现有的「玩家行动优先」说明。

### 6.7 玩家在线这一层参与

- 章末三选一：前情提要加三个下一章方向，或「让它自己走」。复用开局包机制。
- 导演台：列出线与倒计时；可以置顶、静音、新增。透明与盲盒两种模式保留。

## 七、故事蓝图

玩家与 AI 共同维护的长线大纲，整体可选。

- **结构**：总纲（核心问题、基调、候选结局、红线）→ 卷（核心问题、起止状态）→ 里程碑（希望发生的事、前提条件、先后约束、硬性或软性）。里程碑不绑定楼层。远粗近细：只有下一章展开到场面级别。
- **AI 完善**：玩家用自然语言写，AI 返回可逐条接受或拒绝的建议：结构化、补铺垫、对照已发生剧情与设定查矛盾、最多两三个反问。操作：帮我补全、找漏洞、给三种走向、展开这一卷、按最近剧情更新。
- **保护玩家的文字**：每条标明出处（玩家写的、AI 补的）；玩家可以锁定任何一条；AI 的修改只以建议形式出现。
- **影响游玩**：里程碑需要的铺垫进入伏笔账，成为导演的待办；章级规划以最近的里程碑为准；写作模型只看到当前卷的问题、最近一个里程碑的方向与本章该埋的线，完整蓝图只留在导演层；拉力三档（松、中、紧），任何档位下玩家当轮的行动优先。
- **偏离处理**：每章结束检查里程碑状态（已达成、仍可达、受阻、已不可能）。受阻或不可能时给玩家三个选择：调整蓝图、把剧情拉回、放弃。系统不自动改写。
- **版本**：修改按楼层记录、沿路径累加，与导演手记同一做法；分支各有版本，可回看与回滚。
- **剧透选项**：AI 补的部分可以对玩家隐藏，只显示数量。
- **来源与分享**：卡里的章节舞台导入为默认蓝图；蓝图可随世界包导出。

## 八、交互

- **输入区**：「推进」主按钮加三档强度；行动选项以按钮呈现，点击填入、可改；自由输入照常；候选行动里固定一项「让故事自己走」。
- **带原因的重 roll**：重 roll 时可选原因（没推进、没听我的、太短、人设不对、格式乱、别推这条线），下一次生成带着这条纠正；原因写入偏好信号。
- **就地纠正**：选中一段指出问题，重写该段，并记为用户意志。
- **场面控制**：结束这一场、跳到某个时间、调整节奏。
- **正文区**：正文按书页排版；场记的记录（状态变化、伏笔的埋与收、本轮导演动作）以页边批注显示，可关闭。
- **连载视图**：前情提要（隔一段时间回来时显示）、章节目录、人物关系页、时间线、可编辑的记忆、导出成书。
- **每轮成本**：输入、输出、缓存命中率与后台开销显示在输入区下方。
- **卡面图**：角色卡自带的图片（卡片 PNG 本身）作为故事的封面，显示在书架、游玩页标题旁与导入体检页；卡里表现资源表提供的人物立绘显示在人物档案上。图片只读取、不改写，经认证的媒体接口提供；没有图片的卡用按标题生成的占位图。现状：server 与 web 都还没有读取卡面图。

## 九、功能开关

三层，避免旋钮泛滥：

1. **档位**：轻量、标准、沉浸，一键切换。
2. **功能开关页**：按玩家能感知的效果分组；每个开关一句话说明，并显示两个实测数字（每轮花多少、在这个故事里起过多少次作用）。
3. **本轮临时开关**：在输入框旁，只对这一轮生效。

开关清单：场记、档案归档、重逢注入、全文检索、导演（关闭、仅在按推进时、始终）、知情标注、伏笔上限、规则执行、状态面板、行动选项、出图（手动、按章提名、模型主动）、背景音乐、思考档位、工具查阅、写作指令层、原样兼容。卡的作者选项单独一页。默认值按卡自动判断，卡里没有的能力不显示对应开关。

因为原文不可变、视图全部派生，**任何功能都可以中途开关并追溯补算**。这一点写进产品说明。

## 十、其他取舍

- **输出只要正文**：状态栏、选项、图片、变量更新都由程序根据状态渲染或由后台完成，不要求模型输出。
- **插图**：场次归档时由后台提名 0 到若干个「值得画的瞬间」，数量由剧情决定；玩家设置的频率只作为每章上限；保留手动与模型主动触发。
- **工具**：不把多轮调用当成默认更好。默认回合是一次调用加思考；工具按用途开放——卡声明了规则时开放检定工具，设定库超过规模且渠道体检确认模型会用工具时开放查阅，出图按设置。完整的自主循环（深回合）保留为可选功能，不作为发布门槛。
- **人物声音卡**：每个主要人物一份说话样本，只在在场时注入，可从玩家接受过的楼层补充。
- **一分钟开玩**：导入卡、选渠道、进入开场候选；预设降为可选的文风。
- **暂不投入**：插件市场、加深酒馆脚本模拟、新的记忆表示方式、多 agent 讨论。

## 十一、与现有设计的冲突

## 十二、建议顺序

1. **W1 上下文布局**：只改模板顺序与缓存统计，改动最小。
2. **W2 场记**：合并后台调用、事实带引文、节拍标签、场次边界；先验证边界判定。
3. **W3 分型导入与体检页**：决定后面所有东西的输入质量。
4. **W4 导演**：线、八种动作、推进三档、伏笔账、场面卡；从现有 `bits` 引擎演进。
5. **W5 输入交互**：推进按钮、带原因的重 roll、就地纠正。
6. **W6 档案与连载视图**：归档、知情标注、重逢注入、前情提要、章节目录。
7. **W7 故事蓝图**。
8. **W8 功能开关与成本显示**。
9. **W9 界面改版**：按 `docs/proposals/v4-ui.html` 的结构与视觉重做 `packages/web`。

与 R6 的先后：R6 v2 的仪器（G0、重 roll 点回放、遗忘漏斗）与产品无关，可以先做；耗额度的整批对比建议排在 W1–W4 之后，避免给一个马上要改的产品做门槛评测。

## 十三、未验证的假设

- 场次边界的判定是否可靠。
- 动作选择的权重，初版需要靠真人游玩与重 roll 原因校准。
- flash 级模型生成的线与铺垫质量是否够用；不够时章级规划改用更强的模型。
- 公益站与中转渠道是否透传缓存。
- 合并后的场记调用，结算准确率是否不低于独立任务。
- 按在场推导知情，在「转述」「偷听」这类情况下的覆盖率。
