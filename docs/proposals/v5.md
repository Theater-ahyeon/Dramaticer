## 一、AIRP 的第一性原理

### 1.1 玩家要什么

AIRP 是**玩家与模型合写一个自己身处其中的长故事**。玩家既是读者，也是角色。按重要性：

1. **下一段好看**——模型的事；系统只要别往上下文里塞干扰物。
2. **我的选择算数**——写了行动就按我的走；没写时故事能自己往前动。
3. **它记得**——不忘事、不知道不该知道的事、旧线有人收。
4. **不打断**——读和写是一个动作；任何让玩家「管理系统」的时刻都是摩擦。
5. **花得起**——玩家自付 token 与限流额度。

### 1.2 模型的能力边界（2026）

| 擅长 | 不擅长 |
|---|---|
| 文笔、语气、按给定局面写下一段 | 发现自己忘了什么 |
| 长上下文阅读、场景级理解与总结 | 几百楼尺度的一致性 |
| 按少量清楚的约束行事 | 同时满足十几块格式各异的指令 |
| 把文字转成画面描述 | 在单楼碎片里稳定抽出严格结构 |

### 1.3 系统的职责

只做模型做不到、而玩家在乎的事：

- **记得**：把「模型不知道自己忘了的东西」以低噪声递到它面前。
- **守界**：秘密的知情边界、玩家锁定的事实、已死之人不出场。
- **给方向**：玩家想让故事自己走时，提供可选的方向（来自玩家的大纲或原著），不替玩家决定。
- **呈现**：把卡作者做的界面（状态栏、按钮）和插图原样、可交互地呈现出来。

**取舍标准**：每个机制都要回答「它让每百楼带原因的重写次数下降了吗，代价多少」。答不上来的进实验区或删除。

## 三、记忆：三速分层

### 3.1 三层

| 层 | 内容 | 更新 | 体积 |
|---|---|---|---|
| **此刻局面** | 时间、地点、在场者（含姿势/行为/衣着一句话）、关键物品与伤势、当前冲突；秘密 → 谁知道 / 谁不知道；已死之人 | 每楼 1 次轻量增量（与行动选项合并为同一次后台调用） | ≤ 500 token |
| **故事记事** | 每个人物 / 地点 / 势力 / 物品一页，三节：**底色**（卡或原著设定、不可逆转折，只追加）、**现在**（2–3 句，场末刷新）、**经历**（带楼层锚点 `[F12–F20]` 的压缩事件，只追加） | 每场末 1 次**补丁式**编译 | 按需注入 |
| **归档** | 不可变原文、场 / 章摘要、带实体标签的记录、向量 | 场末入库 | 不常驻 |

**世界索引**：每个实体与每条未收的线一行（「白鹭——镇北侯幼女，现在在京城，知道密信内容」），约 200 字，由程序从记事页的一行简介拼出，常驻上下文。解决「模型不会去搜它不知道自己忘了的东西」。

### 3.2 后台调用

| 时机 | 调用 | 产出 |
|---|---|---|
| 每楼落定 | **局面更新**（1 次） | 局面增量（JSON 补丁，程序校验）、2–4 个行动选项 |
| 场结束 | **场末整理**（1 次） | 场摘要、记事页补丁、未收的线更新、入库 |
| 章结束 | **章末清点**（1 次，可配更强模型） | 收线、作废、新开方向 |
| 推进预跑 | 只预跑「推进·一步」 | — |

场的边界：地点或时间明显跳转、在场者大换、或累计 12 楼——由局面更新顺带判定，不另调用。

### 3.3 上下文：六节

1. **卡与写作条目**（含预设注入，ADR-0167）
2. **世界索引**（~200 字）
3. **此刻局面与知情边界**（~500 字）
4. **相关页面**：在场者与重逢者的记事页整页；检索命中时带它所在场的摘要或前后一楼原文（父文档回溯），不塞孤立句子
5. **方向提示**：只在玩家按推进时出现，一两句（来自剧情走向或原著窗口，第四、五节）
6. **最近原文**：放得下就全放；放不下时远粗近细（最近 10–15 楼原文、更早场摘要、再早章摘要）

全部用自然语言小节、统一标题；每节在 Trace 里有来源与 token。

### 3.4 编辑与锁定

- 三张活页（此刻局面、故事记事、剧情走向）像笔记一样**就地修改**；改过的节自动锁定，后台不再覆盖；每次修改是新版本，可撤销。
- 删除变更卡审批流。记事页版本只追加（I4 精神延伸到玩家可见的记忆）。

### 3.5 校验（只拦两件事）

1. 与玩家锁定的事实冲突 → 丢弃该条补丁，记入检视器。
2. 让未知情者知道了秘密 → 丢弃该条，记入检视器。

出处用楼层锚点并宽松匹配原文；格式错误由程序修复。拒收不再因为「引文不逐字」。

### 3.6 与现有代码的关系

复用：只追加记录表（归档层）、状态与秘密投影（局面层数据源）、五路检索、重逢注入、场摘要。新增：记事页存储（分节、按场版本）、场末补丁编译、局面卡渲染、世界索引、父文档回溯、合并后的局面更新调用。删除：场记 / 结算补写 / 事件抽取的分散调用、变更卡审批、逐字引文门禁。

## 四、剧情走向（取代导演）

- **一页两栏**：「想发生的」（玩家与卡写的方向、原著事件，可锁定）与「还没收的线」（场末更新，越老越靠前）。合并大纲、剧情线、伏笔、本场目标、里程碑。
- **推进**：后台已备好 2–3 个方向（取自走向页或原著窗口），以菜单给玩家点选；一步 / 一场 / 跳跃作为菜单里的范围选项。
- **玩家写了行动就什么都不加**（保留「不干扰玩家」）。
- **删除**每拍的程序动作选择（八种动作）与 `mechanisms` 引擎；保留章末清点。
- **写法**：默认快速；规划、深度移入设置里的「实验」（仍只能玩家手动切换，I6）。

## 五、原著同人：导入长篇小说

> 人类 2026-11-20 新增需求：导入长篇小说原文，按原著玩同人卡。参考人类本机的「原著指导」卡。

### 5.1 参考卡做对了什么

「原著指导」卡（作者本机，未入库）离线把一部小说预处理成：

- **事件轨道**：一条按剧情顺序排列的事件表，每件有内部时刻、标题、概要、缩写、参与人物、对应原文段落、**话术**（人物原话，区分「说」与「想」）。
- **滑动窗口注入**：窗口左边（已演过）不发、窗口内发、右边（未来）不发以防剧透。窗口里分「当前」（时刻已到，该演）和「接下来」（可能的走向，不提前写）。可叠加「含缩写」「含话术」，或改发「原文」。
- **时间驱动推进**：模型每轮写内部时刻；时刻走到哪件事就轮到哪件；玩家明确要开始某件事时直接推进到它，中间的简要带过。
- **偏离规则**：原著只是参考；与本局已发生的事实冲突时以本局为准；玩家偏离时顺着玩家写，不把剧情拽回原著；关系、称呼以本局为准。
- **在场即带设定**：在场的人，其人物条目本轮必进上下文。
- **生死**：已死之人不出场；窗口里涉及死人的事件标注「已死，本局不再出场」，并剔除其话术。
- **名册预登记**：原著全部人物预先登记，登场时只改在场。
- **开局器**：选书、选开局时刻（与玩家扮演的身份）；「自由模式」可以把窗口拖到任意事件「从这里开始」。
- **玩家改原著**：在原著页改事件的标题 / 概要 / 话术 / 原文段落，按格对照，不按位置猜。
- **推进 N 件**：只记待办，玩家下一次带着自己的话生成时一起推进（「必须夹带玩家的输出」）。

它的局限：靠作者离线跑 Python 管线、发布资源包；每本书都要作者手工做一遍；依赖 MVU 变量、酒馆助手脚本与世界书扫描三套机制拼起来。

### 5.2 我们的做法：原生「原著」

Dramaticer 把上面这套做成**原生功能**，任何玩家导入任意一部小说都能用，并与记忆、剧情走向共用同一套数据：

| 原著指导卡 | Dramaticer 原生 |
|---|---|
| 离线 Python 预处理 | 导入时后台按章抽取（可暂停、可续跑、先报预估 token） |
| 事件轨道 | **原著事件表**（新存储） |
| 人物条目、名册预登记 | 原著人物直接建成**故事记事**页的「底色」，名册即记事页 |
| 滑动窗口注入 | 上下文第 5 节「方向提示」的原著来源：当前 + 接下来，可选话术 / 原文 |
| 内部时刻推进 | **原著游标**：由局面更新顺带判断「本楼演到了哪件事」，不要求模型写时刻格式 |
| 在场即带设定 | 已有：在场者记事页整页注入（3.3） |
| 生死 | 局面层的「已死之人」；原著窗口自动标注、剔除话术 |
| 偏离规则 | 写入方向提示的固定说明；本局记事与局面优先于原著 |
| 开局器、自由模式 | 新建故事弹窗里的「从原著开局」：选扮演身份（原著人物 / 自创人物）与开局事件；故事中可在原著页「从这里开始」 |
| 玩家改原著 | 原著事件可就地编辑，按格版本化（同 3.4） |
| 推进 N 件 | 推进菜单里的「推进到下一件 / 推进 N 件」，与玩家本轮输入一起生效 |
| 原文按章存浏览器 | 原文入库（`data/`，玩家本机），按章分段、可检索 |

### 5.3 导入流程

1. **上传**：txt / epub（先做 txt；编码自动识别 UTF-8 / GB18030）。
2. **分章**：按「第 N 章 / 卷 / Chapter」等标题规则切分，界面可预览、手动合并或拆分。
3. **预估**：显示章数、字数、预计后台 token 与费用（按所选后台模型），玩家确认后开始。
4. **按章抽取**（后台任务，可暂停、续跑，进度可见；每章 1 次调用）：
   - 事件：标题、一句话概要、缩写（3–5 句）、参与人物、地点、相对时间（「三日后」）、对应段落范围；
   - 话术：本章重要人物的代表性原话（说 / 想），每人每章最多数条；
   - 实体增量：新出场的人物、地点、势力、物品，及已有实体的新信息。
5. **全书汇编**（一次后台任务，分批）：合并同名与别名、排定事件顺序与相对时间线、生成每个实体的记事页「底色」与一行简介、标记关键转折。
6. **成卡**：生成一个「原著故事包」，可直接开局，也可与现有角色卡组合（卡提供文风与规则，原著提供世界与时间线）。

所有原文与抽取结果只存在玩家本机 `data/`；导出故事包时由玩家决定是否包含原文。

### 5.4 游玩时

- 上下文第 5 节在**每一轮**都给原著窗口的「当前」一件（不只是推进时），「接下来」1–3 件只在推进或玩家明确要推进时给；话术与原文按设置叠加，默认「概要 + 话术」。
- 局面更新每楼判断原著游标：本楼是否演完了「当前」事件；玩家偏离时游标不动，原著事件变为「还没发生」而不是强推。
- 剧情走向页的「想发生的」默认就是原著事件序列，玩家可以删、改、锁、插入自己的事件。
- 原著页（记事里的一个分页）：事件轨道可视化，已演 / 当前 / 未来，点开看概要、话术、原文；「从这里开始」。

### 5.5 成本控制

- 抽取是一次性的；按章 1 次调用，一部 200 万字的小说约 500–800 章，后台 token 量在导入前明确告知。
- 抽取结果可导出为原著包分享（不含原文时不涉及版权文本），他人导入后无需重跑。
- 游玩时不额外增加每楼调用：原著游标判断并入局面更新。

## 六、剧情插图（参考智绘姬）

### 6.1 智绘姬的工作方式（读源码与设置所得）

- 每次 AI 回复后（自动或按钮），调用一个独立的「生图 LLM」：系统提示词 + 最近 N 楼（默认 2）+ 触发的世界书 + **按关键词触发的标签库条目**（动作、姿势、构图、表情、服饰等分类，每类一段 Danbooru 标签参考）。
- LLM 按固定格式输出多张图（数量可设，如 3–4 张），每张：
  - 插入位置（原文里的一句，用来定位插图在正文中的位置）
  - 标题、画面思考（一段浓缩描述）
  - `Scene Composition`（构图、背景）+ 每个人物的 `Character N Prompt`（含坐标）与 `Character N UC`（人物级负面）
- **角色调用**：LLM 不直接写外貌标签，而是写 `${"name":角色, "angle":视角, "upperBody":"sfw|nsfw|hidden", "lowerBody":…}$`；程序从**角色库**展开成固定标签。角色库每人分「脸部 / 上身 / 全身 × 正面 / 背面 × 穿衣 / 裸露」；服装库按「上身 / 全身 × 可见 / 隐藏」，归属某个角色。这是它一致性的核心：外貌由程序保证，模型只决定姿态与可见范围。
- 提示词替换规则（含正则、条件）、去重、全角标点清洗。
- NovelAI 请求：V4 及以上用 `v4_prompt.caption.char_captions[{char_caption, centers:[{x,y}]}]`、`v4_negative_prompt` 同构并 `legacy_uc:false`、`characterPrompts[{prompt, uc, center, enabled}]`、`use_coords`（「AI 默认位置」开时不用坐标）；V5（`nai-diffusion-5-full/curated`）用 `params_version: 4`，不发 `skip_cfg_above_sigma` 与旧参考图数组，噪点表默认不发，有 `tag_hint_uc_preset`、`tag_hint_qt`、`straight_alpha`，「Medium 档」换模型为 `nai-diffusion-5-full-medium`；负面预设 Heavy / Light / Human Focus / Furry Focus / None；返回 zip 取 PNG。
- 其他：氛围转移（vibe）与角色参考组、云端排队避 429、生图间隔、图片缓存、长按改提示词、双击重绘、任务管理（可取消）。

### 6.2 我们的做法

| 智绘姬 | Dramaticer |
|---|---|
| 独立「生图 LLM」，每楼调用 | 后台岗位「画面整理」，间隙里运行；默认**每场末 1 张**或玩家手动「画这一幕」，可设为每楼 |
| 按关键词触发的标签库条目 | 原生「标签库」：分类条目，按正文关键词触发进整理提示词（与写作条目同一套数据结构） |
| 角色库 / 服装库，按部位与可见性展开 | **视觉档案**扩展：人物按「脸 / 上身 / 全身 × 正 / 背 × 着装 / 裸露」分格，服装独立并归属人物；整理输出只写「谁、视角、哪些部位可见、穿哪套」，程序展开 |
| 正文里的插入位置 | 插图挂在楼层上并记录「插在第几段后」；显示时插到对应段落（不改原文，I8） |
| 世界书触发 | 记事页（在场者）与世界索引作为整理的输入 |
| 多人物 caption + 坐标 + 人物级负面 | 同：NovelAI V4+ 多人物请求；坐标可由整理给出或关闭用默认 |
| 提示词替换、去重、清洗 | 程序后处理：去重、全角标点清洗、替换规则（正则） |
| V5 参数差异 | 模板按模型族生成请求体（V3 / V4.x / V5 三套），Medium 档、负面预设、straight alpha |
| vibe、角色参考 | 第二期：模板可挂参考图（存故事媒体） |
| 云端排队 | 不做第三方排队；本地队列 + 429 退避 + 每分钟上限 |

## 七、卡片前端：渲染插件

现状：沙箱渲染器 `SandboxBlock` 与酒馆助手沙箱 `buildStHelperSandboxDocument` 已实现，但**都没有接进故事页**。人类日常使用大量依赖卡片前端的扩展（状态栏、手机界面、MVU、EJS），这是兼容入口里最影响体验的一块。

- **楼层渲染器扩展点**（插件内核）：插件声明认领的块或正则，返回在 `sandbox="allow-scripts"` iframe 里运行的内容；高度自适应；主题变量传入（I8：从原文派生，不改原文）。
- **交互桥白名单**：发送消息、填入输入框、读变量、经结算器写变量、打开图片；未声明的调用拒绝并记入检视器（I16、I18）。
- **第一个渲染插件**：`st-content` 的美化正则（显示层）+ `st-helper-host`：卡的状态栏、选项面板、开局器在故事页原样显示并可点击。
- **变量**：卡脚本读写的 MVU 变量映射到状态的 `mvu.*` 命名空间（已有 `st-mvu`），写入走结算器。

### 8.2 故事页

- 输入台默认：行动选项（点击直接发送；铅笔填入修改）、输入框、主按钮。**有字时是「发送」，空时是「推进 ▾」**（下拉里是方向菜单与一步 / 一场 / 跳跃 / 推进到原著下一件）。Enter 发送、Shift+Enter 换行（手机端 Enter 换行）。
- 写法、批注收进输入台左下「⋯」；token 与耗时只在检视器。
- 每楼悬停（手机长按）：重写（可选原因）、改这句、从这里分支、看上下文。
- 撤回导演安排：「仅撤回」/「撤回并重写」。
- 开场白立即显示为第 0 楼；多开场白左右切换；开局候选以卡片显示。
- 批注默认关；开着时说人话，不显示内部路径。
- 状态块与卡片界面走渲染插件；插图插在对应段落之后。
- 手机端：输入台默认一行、聚焦展开；正文区至少 70% 高度；底部导航 5 项以内。

### 8.3 文案规则与首批对照

界面只用人话和标准软件术语：不写解释架构的句子，不用文艺腔，不用「它」指代模型，占位符只说操作。

| 现在 | 改为 |
|---|---|
| 这里没有路 / 灯塔照不到这一页 | 页面不存在 |
| 它看到了什么 | 上下文 |
| 写下你的行动或台词。只要你写了，导演就不插手 | 输入行动或对话 |
| 哪里不满意？ | 重写原因（可选） |
| 这不是我要的 | 撤回 |
| 不想 / 想一下 / 多想 | 关闭 / 低 / 高 |
| 省 / 均衡 / 全开 | 轻量 / 标准 / 完整 |
| 还能走到 / 走不通了 / 已发生 | 进行中 / 已偏离 / 已达成 |
| 没认出 | 未分类 |
| 还没有写下第一楼 | 暂无内容 |
| 条剧情线在走 / 个伏笔没收 | 剧情线 N · 未收的线 N |
| 记忆与导演暂停了……正文照常能写…… | 后台任务连续失败 N 次：原因。〔检查渠道〕 |
| 每一项都能随时开、随时关…… | （删除） |

## 十一、风险

| 风险 | 应对 |
|---|---|
| 场级抽取延迟：场内的事实只在局面层 | 局面层每楼更新；场末前的细节在最近原文里 |
