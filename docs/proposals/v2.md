# Dramaticer v2 设计提案（2026-11-07，已获人类确认）

> 本提案由人类与设计者在 M3 完成后共同确定，用于取代 DESIGN.md 中与之冲突的部分。开发 agent 分拣 INBOX 时，按第十节把它合并进 DESIGN、DECISIONS 和 TASKS。

## 〇、为什么要改

M0–M3 的实测暴露了三个根本问题（证据见 `docs/dev/reports/M2.md`、`M3.md`）：

1. **主模型不会主动写结构化数据**：90 个生成楼层里 `plot_note` 为 0，`state_update` 也没有触发。没有 MVU 的卡，状态层是空的。
2. **Director 没有输入，指令又空泛**：线索、事件池、场景三个机制都缺少输入；节奏机制只会输出笼统的话。重复度 0.0915 对 0.0940，差值在噪声范围内。
3. **记忆的核心对比没有做成**：逐楼抽取太慢，事件表一直没有建立起来；融合检索的 @5 低于单用 BM25。

社区里三个成熟方案（柏宝书、故事神谕、DSH Tavern）都给出了同一个答案：**状态和台账由后台结算，不指望主模型主动写；剧情方向由"规划"提供具体方案，而不是空泛的提醒。**

## 一、核心原理

> 玩家读回复、打字的那段时间（间隙）是免费的算力。能提前做的思考都在间隙里做完；回合内只做必须看到玩家输入才能做的事。

| 时机 | 做什么 |
|---|---|
| **间隙**（回复落定后 → 玩家发下一句前） | 结算台账、批量抽取事件和线索、压缩、为下一轮预筛世界书、预先规划下一拍、准备候选行动、一致性检查（不阻塞） |
| **快回合** | 一次主调用，上下文全部预先备好；模型可以按需调用本地读取工具 |
| **深回合** | 单 agent 循环：模型自行决定规划、查资料、写作、自检的方式和步数 |

## 二、两种回合模式（玩家手动切换）

- **玩家手动切换**：输入框旁边有一个"快 / 深"开关；可以对单轮生效，也可以锁定整个故事。**程序不自动切换。**
- **快回合**：一次主调用 + 预先备好的上下文；模型可以调用本地读取工具（`memory_search`、`ledger_read`、`lore_lookup` 等），软上限默认 3 轮。
- **深回合**：同一个 agent 循环，开放全部工具（记忆、台账、世界书、剧本、原作资料包、历史回溯，以及可选的联网搜索）。**由模型自己决定要不要规划、查多少资料、要不要自检。** 只设防止失控的上限：默认最多 40 次工具调用或 10 分钟，可以配置。界面实时显示进度（"回忆中……""查阅设定……"），正文流式输出。
- **渠道兼容**：渠道体检判定工具调用稳定的，走原生函数调用；不稳定的，走文本协议（模型输出 `<tool>…</tool>`，由程序解析执行）。两种方式跑的是同一个循环。

## 三、模型能动性原则

harness 为模型**提供信息和选项，不下剧本式的命令**：
- 导演指令是"建议"，模型可以不采纳；注入时附带"玩家行动优先，你可以按剧情需要调整"。
- 写作契约只保留少量原则（见第六节），不规定固定的输出结构和段落格式。
- 不强制模型每轮调用工具，也不强制输出结构化块。结构化数据由后台结算器补齐；模型主动写了，就以模型写的为准。
- 预算上限只用来防止失控，不用来压缩模型的思考。

## 四、台账：唯一的事实来源

台账采用事件溯源：每楼存 diff，沿路径累加，分支切换时自动正确。
- **人物**：身份、外貌、当前衣着与状态、位置；分主演和龙套两级
- **关系**：有方向；类型、阶段、转折点；好感分内在和外在（五档文字），有惯性，没有充分依据不调整
- **物品**：持有者、位置、来历、变动日志（不重复结算）
- **场景**：从大到小的地点树；当前现场（在场人物、姿势、氛围）
- **时间**：故事内时间锚点
- **线索**：伏笔、约定、谜题；开启 → 推进 → 兑现
- **知情表**：谁知道什么
- **用户意志**：玩家明确表达过的偏好、底线和纠正（永远有效）

有 MVU 的卡，MVU 变量映射为台账里的一个命名空间；没有 MVU 的卡，使用上面的默认结构。

**结算器**（后台）：每次回复落定后，抽取台账变更（可以批量处理多个楼层）。模型主动写了就以模型的为准；没写就补上；写坏了就修复，并记录修复原因（借鉴故事神谕的诊断模式）。

## 五、记忆分层

| 层 | 内容 |
|---|---|
| 现场 | 最近 N 楼原文 |
| 楼层摘要 | 每楼一段结构化摘要，带时间锚点（后台批量生成） |
| 章节压缩 | 八段式：剧情脉络 / 人物档案 / 关系网 / 世界与设定 / 物品与资源 / 伏笔与约定 / 当前情况（含暗线）/ 用户意志 |
| 主线 | 跨章节概览 |
| 事件索引 | 只追加，多路融合检索，知情者过滤（批量抽取，一次调用处理一个窗口） |
| 原作资料包 | 同人卡的原作知识，每条事实标注原作时间点，超过设定时间点的不注入 |
| 玩家画像 | 跨故事学习玩家口味，需要玩家确认 |

上下文预算不够时的取舍顺序：用户意志 > 人物关系 > 未兑现线索 > 当前生效设定 > 历史细节 > 现场描写。

世界书由后台**为下一轮预先筛选**：先用 BM25 便宜地预筛，再由后台模型判断相关性。

## 六、写作契约（原生主提示词的核心，保持精简）

- 玩家的输入是"本轮演出指引"，不是已经发生的剧情：要重新组织场景来演出它，不要接着原句往下写。
- 玩家不是上帝：其他角色可以按人设拒绝、反对、打断。
- 每一轮都有剧情意义，不重复之前的正文。
- 遵守台账里的"用户意志"。

社区预设（破限、文风）叠加在上面；写作契约放在最靠近生成的位置。

## 七、Director v2

- **长线层**（后台生成，玩家可以编辑）：弧线 = 贯穿线 + 路标 + 难度 + 红线；序列 = 一组节拍，每拍包含目标、起始迹象、契合点（具体到人和事）。来源可以是：根据卡、台账、未兑现线索自动生成；侧边"参谋"和玩家商量得出；导入的剧本。
- **短线层**（每轮由程序选择，不调用模型）：当前拍 + 强度（只铺垫 / 自然推进 / 尽快引爆）+ 纠偏信号（重复、停滞、线索太老、节奏阶段），从后台准备好的具体方案里挑一条。**注入时并进玩家消息末尾**，并且只作为建议。
- **落拍检测**：结算器顺带判断这一拍是否完成，完成了由程序翻到下一拍。
- **候选行动**：间隙里准备好 4 个行动加 1 个场景变化，玩家点一下就填进输入框，不会自动发送。
- **透明和盲盒两种模式**；NPC 幕后议程以"与此同时"的形式回到剧情里。

## 八、侧边 agent（不进入正剧）

- **资料员**：为同人卡调研原作（来源包括联网和本地小说），产出原作资料包草稿，玩家确认后启用。
- **参谋**：和玩家商量剧情走向，产出弧线和序列。
- **卡片工坊**：读写角色卡和世界书。
- **去 AI 味校正**：修正结果作为一个新的 swipe，原文不动。

## 九、评测（能挡住进度的门槛）

| 指标 | 测法 |
|---|---|
| 矛盾率 | 长程自动试玩中定期插入回忆型探针，LLM 裁判对照台账判断 |
| 对比胜率 | 盲测两两对比（LLM 裁判，交换顺序消除位置偏差） |
| 重复度、推进度、NPC 主动性 | 文本统计加 LLM 裁判 |
| 首字延迟 P50/P95、每轮成本 | 分快回合和深回合统计 |
| 深回合的增益 | 同一个分支点，快回合和深回合各生成一次，做两两对比 |

**基线**：
- **B0 朴素模式**（Dramaticer 内置：卡 + 预设 + 最近 N 楼，没有记忆和导演），使用我们自己的渠道。
- **B1 历史回放基线**：玩家真实的 ST 对话本身就是"ST + 插件"的产物。在同一个分支点，让 Dramaticer 续写一段，和当时 ST 的真实回复做两两对比。**不调用本地 ST，零额度。** 这是主力基线。
- **B2 本地 ST 实测**（可选、小样本）：只在里程碑门槛时使用；每次使用前都要在 HUMAN.md 里申请并得到确认；单次门槛最多生成 60 次。**本地 ST 的额度属于玩家，能不用就不用。**

**门槛规则**：没有赢过基线，就自动生成改进任务，然后重新评测，最多三轮；之后写进 HUMAN.md 请人类决定。不允许"记一笔未证实，然后继续往下做"。

## 十、执行顺序（接在 M3 之后，替换 M4 剩余任务的位置）

| 阶段 | 内容 |
|---|---|
| **R1 世界模型** | 台账默认结构与 MVU 映射；结算器（补写、修复、原因）；批量事件抽取，并为 3 个评测对话建好事件表、重跑 M2 记忆评测、调整融合权重；八段式压缩；后台预筛世界书；用户意志捕获 |
| **R2 评测底座** | B0 朴素模式、B1 历史回放基线；长程自动试玩命令行（LLM 扮演用户）；一致性探针；盲测两两对比；`docs/dev/SCOREBOARD.md` 记分牌 |
| **R3 双模式回合** | 快回合与深回合、手动开关、文本协议兜底、写作契约、进度事件、防失控上限 |
| **R4 Director v2** | 弧线和序列、后台规划器、落拍检测、候选行动、注入玩家消息 |
| **R5 能玩的界面** | 继续 M4：server、SSE 聊天、模式开关、台账面板、导演面板优先；其余面板延后 |
| **R6 效果门槛** | 对 B0 和 B1 达标（必要时 B2），否则自动迭代 |
| **R7 之后** | 侧边 agent（资料员、参谋、卡片工坊、校正）→ 兼容线 → alpha → 生图 → Tauri |
