# Dramaticer v2.1 补充提案（2026-11-07，已获人类确认）

> 这是 v2（`docs/proposals/v2.md`，已由 ADR-0033 合并）的补充。参考来源：Talemate、Luker 记忆图谱、Letta 睡眠时计算、Zep/Graphiti、Drama Llama/Dramamancer、ST 社区记忆插件、Tencent WeKnora。
>
> **原则：外部项目只能证明"有人这样做，并且能跑起来"，证明不了"在 RP 里效果更好"。** 所以本提案分成三类：风险低、收益明确的**直接采纳**；改变架构的**只预留接口、用评测决定**；面向特定卡型的**暂缓**。

## 一、直接采纳

| 编号 | 内容 | 落到哪里 | 来源 |
|---|---|---|---|
| A1 | **现场分析**：间隙里由后台生成一小段，写明在场每个人物此刻想要什么、各自知道什么、场面上的张力在哪里，作为下一轮上下文里的一个槽位 | R1（新增任务，依赖结算器） | Talemate 的场景引导 |
| A2 | **上下文包复用**：间隙里准备好的检索结果、预筛的世界书、现场分析，打包挂在玩家楼层上；swipe 和重新生成时直接复用，只有玩家编辑了输入才重新计算 | R1 或 R3 | Luker |
| A3 | **自然语言修订记忆**：玩家用一句话提出修改，系统生成台账**变更卡**（可以批准、拒绝、回滚）；批准后写成来源为 `player` 的事实，优先级最高，同时记进"用户意志" | R1-T07 扩展，或新增任务 | Luker 的 AI 修订、WeKnora 的需确认记忆 |
| A4 | **父子分块**：检索时匹配小块，命中后注入它所在的整段或整楼 | R1-T04.b 重跑记忆评测之前 | WeKnora |
| A5 | **重排序**：多路融合之后加一个重排序模型（例如硅基流动的 bge-reranker），解决事件题 @5 偏低的问题；用 M2 的记忆评测验证，没有提升就关掉 | 同上 | WeKnora |
| A6 | **评测补充**：记忆题按 LongMemEval 的五类出题（信息抽取、跨段推理、时间推理、知识更新、拒答）；新增**编造回忆率**（问一件从没发生过的事，看模型会不会编）；叙事质量用参考 TTCW 的评分表（独创性、人物发展、节奏、对话）；**裁判模型和写作模型不能是同一家** | R2-T03、R2-T04、R2-T06 | LongMemEval、Drama Llama |
| A7 | **深回合工具少而通用**：以"搜索、阅读页面或条目、读写台账"为核心，加上可选的联网搜索，不要为每种数据各开一个工具 | R3-T00 细化时 | WeKnora v0.8.2 |
| A8 | **深回合运行中追加要求**：深回合跑到一半时，玩家可以补一句要求，不需要中断重来 | R3 | WeKnora |
| A9 | **模型按岗位配置**：写作、结算与抽取、规划与条件判断、评测裁判，各自单独配置渠道和模型 | R1-T02 或 R2（配置层） | Talemate、omp 的角色设计 |

## 二、只预留接口，用评测决定

**现在就做（几乎零成本）**：R1-T01 的台账事实里多存两个字段：
- `storyTime`：事实成立的故事时间段（起、止；未知可以为空）
- `source`：事实来源，取值为 `model`、`settler`、`player`、`import`

有了这两个字段，以后无论切换到哪种表示方式都可以平滑迁移。

**R2-T99 之后的对比实验**（新增任务，排在 R3 之前或和 R3 并行）：

| 实验 | 候选方案 | 判定依据 |
|---|---|---|
| X1 世界模型的表示方式 | ① v2 的简单台账；② 台账（硬事实）+ **实体 Wiki 页**（软知识：性格变化、关系史，带出处楼层，有版本历史）；③ 时序知识图谱（事实被标记为失效，而不是删除；支持按时间点查询） | 矛盾率、编造回忆率、盲测胜率、每轮成本。**只有显著胜出才切换**，否则保留 ① |
| X2 Director 的组织方式 | ① v2 的方案和序列；② **剧情小品引擎**：只有一种对象，条件可以是自然语言或台账查询；在间隙里一次调用批量判断所有条件；支持冷却、顺序约束、可否重复、兜底；卡作者可以在 `extensions.dramaticer` 里附带自己的小品 | 重复度、推进度、线索兑现率、盲测胜率，以及条件判断的准确率（人工抽样核对） |

实验的设计和结果都写成 ADR；人类只需要看最终结论。

## 三、暂缓（基础效果达标之后再说）

- **卡片技能**：修仙境界、战斗规则这类机制知识做成按需加载的文档
- 深回合里可选的"规划-批评-执行"工作方式
- **程序化检定工具**：掷骰、属性检定、资源消耗
- **可选集成 WeKnora**：资料员通过 MCP 调用 WeKnora 来处理原作资料（不作为依赖）
- 对外提供 MCP Server，让外部 agent 查询故事数据

## 四、不变量

不需要修改。A1–A9 都符合 I6、I7、I9、I11–I14；X1 和 X2 是实验，不改变现有的不变量。
