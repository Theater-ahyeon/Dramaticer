# 规格：导演不干扰玩家

> 设计出处：v4 第十七节。命名按 `GLOSSARY.md`。

## Problem Statement

玩家写了自己的行动，导演仍然往这一楼里塞安排；玩家想慢慢聊，导演嫌没进展而催。

## Solution

导演只在玩家把方向交出来（按推进，或说「继续」这类话）时出手，其余时候什么都不加；每条安排都能一键撤回。

## User Stories

1. 作为玩家，我写了一句很短但明确的行动（例如三个字），希望这一楼只照我写的发展
2. 作为玩家，我按推进时，希望导演给出具体到人和事的下一步
3. 作为玩家，我正在自己写的时候，不希望倒计时到点的事件打断我
4. 作为玩家，我想安静聊几楼时，不希望被制造阻碍
5. 作为玩家，我做的事应该能让一条剧情线提前结束或转向
6. 作为玩家，我看到不想要的安排时，能点一下撤回并让那条线不再出现
7. 作为玩家，我希望导演默认只在我按推进时工作

## Implementation Decisions

- 意图判断由纯程序完成：推进按钮、行动选项、固定说法的短语表；不再用字数门槛
- 不干预时导演槽位为空，决策记录仍写入 Trace
- 突发有「延后」状态，随下一次推进或场次结束触发；必须打断的事件每场最多一次
- 「过于顺利」只在推进时参与选择
- 撤回写入偏好并静音对应剧情线；重写原因里的两项用于统计干扰比例

## Testing Decisions

- 只测对外行为，不测实现细节。
- 在导演动作选择这一层测：给定玩家输入与剧情线状态，断言选出的动作与注入内容。沿用现有 lines 相关测试的写法。
- 单元测试不访问网络、不使用私有数据（I10）。

## Out of Scope

导演的八种动作本身、章级规划的算法不改。
