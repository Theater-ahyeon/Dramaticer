# 规格：新界面

> 设计出处：docs/proposals/v4-ui.html、v4 第十九节。命名按 `GLOSSARY.md`。

## Problem Statement

现在的界面看不出这个项目和聊天框的区别；记忆、导演、上下文都藏着；手机上不好用。

## Solution

按原型重做 packages/web：印章式导航、手稿式正文加批注、玻璃输入台、三个停靠页、可就地修改的记忆页、大纲、设定、设置和命令面板。

## User Stories

1. 作为玩家，我打开就能从书架接着上次的故事写，并看到上回说到哪
2. 作为玩家，我看到卡自带的图片作为封面
3. 作为玩家，正文像书页一样好读，旁边能看到这一楼记下了什么
4. 作为玩家，我用一个按钮推进，并能选一步、一场或跳跃
5. 作为玩家，我能在输入框旁切换写法并看到每一楼花了多少、等了多久
6. 作为玩家，我重写时点一下原因
7. 作为玩家，我在右侧随时看到剧情线和倒计时
8. 作为玩家，我能点开看这一轮模型看到了什么，并直接跳去修改
9. 作为玩家，我在记忆页点任何一句就能改
10. 作为玩家，我能和 AI 一起维护大纲
11. 作为玩家，我能改这个故事的设定
12. 作为玩家，我用一个档位或逐项开关控制功能
13. 作为玩家，我按 Ctrl K 跳到任何地方
14. 作为手机玩家，所有这些在窄屏上都能用

## Implementation Decisions

- 视觉与结构以原型为准：颜色与字体的变量、各页的 data-view、组件的类名可直接对照
- 界面文字只用 GLOSSARY.md 的名字
- 数据全部来自 server 接口；web 不直接引用 core 的运行时
- 新页面逐个替换旧页面，每张工单结束时门禁与端到端测试保持通过

## Testing Decisions

- 只测对外行为，不测实现细节。
- 每张工单补一条 Playwright 端到端用例，覆盖桌面与手机两个视口；沿用现有 e2e 的种子与启动方式。
- 单元测试不访问网络、不使用私有数据（I10）。

## Out of Scope

面板编辑、插件市场、Tauri 打包。
