# 规格：记忆层

> 设计出处：v4 第十六节。命名按 `GLOSSARY.md`。

## Problem Statement

几百楼后角色忘事、串戏；后台模型改写旧记忆会累积错误；玩家看不到也改不了系统记住了什么。

## Solution

原文是真相；后台只追加带出处的记录；状态和秘密由程序从记录里算出来；百科页面由记录汇编；取用时看谁在场。

## User Stories

1. 作为玩家，角色的位置、衣着、伤势、持有物在几十楼后仍然对得上
2. 作为玩家，久未出场的人物再登场时，记得上次见面的情形与当时的关系
3. 作为玩家，不在场的角色不会知道他没听到的事
4. 作为玩家，角色的态度变化有来龙去脉可查
5. 作为玩家，我能看到每条记忆出自哪一楼的哪句话
6. 作为玩家，短故事里不为记忆多花调用
7. 作为玩家，我纠正过的写法以后不再犯
8. 作为玩家，我能看到这一轮模型实际看到了什么

## Implementation Decisions

- 现有事件索引升格为只追加的记录，带实体、故事时间、重要度与逐字出处；结算事实也以记录追加
- 状态是记录的确定性投影；卡可以声明类型、频率与常驻
- 秘密是独立的小表；在场即知道，其余由自动记录显式标出
- 检索三路融合，实体这一路由在场者与玩家提到的名字驱动，按故事时间排新旧；重要记录带回原文摘录
- 百科页由记录汇编，语句带出处与有效范围；章末做一次反思
- 偏好来自纠正与重写原因
- 提供「本轮上下文」的读取：每一类的大小与每一条的来源

## Testing Decisions

- 只测对外行为，不测实现细节。
- 在存储与上下文组装两个接口处测：写入若干楼，断言记录、状态、秘密与组装出的上下文。沿用现有记忆与台账测试的合成 fixture。
- 单元测试不访问网络、不使用私有数据（I10）。

## Out of Scope

外部记忆服务、知识图谱存储、让后台模型更新或删除旧记录。
