# 规格：三种写法

> 设计出处：v4 第十四节 14.2–14.4、14.8。命名按 `GLOSSARY.md`。

## Problem Statement

flash 级模型一次调用顾不过来；深度写法现在没有给模型任何改稿的理由，90 轮零工具调用。

## Solution

三种写法由玩家手动选：快速写一遍；规划按固定阶段先理清再写，并趁玩家在想时提前备好；深度是起草、自查、修改、交稿。

## User Stories

1. 作为用 flash 级模型的玩家，我选规划后角色不再串戏、状态不再对不上
2. 作为玩家，我点推进或行动选项时不用多等
3. 作为玩家，我自由输入时能看到它正在挑记忆、定计划
4. 作为玩家，我选深度时能看到草稿、自查的每一项和修改
5. 作为玩家，深度写出来的一楼不重复上两楼的节拍
6. 作为玩家，模型不按流程走时我仍然能得到一楼正文
7. 作为玩家，界面按我的模型告诉我推荐哪种写法

## Implementation Decisions

- 规划的阶段：挑记忆与设定、在场角色各凭自己知道的事提出意图、本轮计划、正文、可选的复查（存成可切换的版本，不阻塞显示）
- 提前备好在间隙对推进三档与每个行动选项跑完准备阶段，命中时回合内只剩正文
- 深度：回复是工作区里的草稿文件；读、搜、写、打补丁、交稿、结束六个工具；自查清单由程序从状态、秘密、最近节拍、偏好、待埋伏笔生成；故事数据呈现为文件树；直接输出照常接住
- 写法只由玩家切换（I6）

## Testing Decisions

- 只测对外行为，不测实现细节。
- 用脚本化的假模型在回合入口处测：阶段顺序、命中与未命中提前备好、深度的工具序列与兜底。对照评测用 R6 v2 的仪器。
- 单元测试不访问网络、不使用私有数据（I10）。

## Out of Scope

多个 agent 来回讨论；自动切换写法。
