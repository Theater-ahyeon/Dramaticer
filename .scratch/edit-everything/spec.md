# 规格：一切可改

> 设计出处：v4 第十五节。命名按 `GLOSSARY.md`。

## Problem Statement

系统记错了、设定不合心意、规划走偏了，玩家只能干看着，或者绕道让助手生成变更卡。

## Solution

除楼层原文外，每一项都能看、能改、能撤销；玩家自己的修改不用批准，改过的自动锁定。

## User Stories

1. 作为玩家，我能改这个故事用的设定条目，而不影响卡库里的原卡
2. 作为玩家，我能把设定恢复成卡的原样
3. 作为玩家，我能直接改状态里的任何一个值
4. 作为玩家，我改过的内容不会被后台重新整理时覆盖
5. 作为玩家，我能看到一项内容的修改历史并回到之前的版本
6. 作为玩家，我删掉的记忆可以找回
7. 作为玩家，我能锁定大纲、剧情线里的任何一条
8. 作为玩家，我在一条分支上的修改不影响另一条分支

## Implementation Decisions

- 设定在故事创建时固定一份副本，修改只作用于副本
- 玩家的修改走与后台相同的格式校验，不走变更卡，来源记为玩家并自动锁定
- 后台与 AI 对锁定项只能提建议
- 修改沿楼层树记录，默认从当前楼起生效
- 删除是停用

## Testing Decisions

- 只测对外行为，不测实现细节。
- 在各自的修改接口处测：修改、校验失败、锁定后后台写入被拒、回滚、分支隔离。
- 单元测试不访问网络、不使用私有数据（I10）。

## Out of Scope

楼层原文的修改（仍然是新建兄弟节点）；多设备同步。
